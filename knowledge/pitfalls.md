| Симптом | Причина | Правило |
|---|---|---|

## Память, порты и процессы

| Симптом | Причина | Правило |
|---|---|---|
| `curl` падает с кодом 23 | переполнение `/tmp` (tmpfs 993 МБ) | тяжёлое — в `/tmp` только при нужде; полные тарболы не качать |
| снимок workspace обрезан, свежие папки пропали | `/home/user` разросся (>128 МБ) | держать воркспейс компактным, дубли данных удалять |
| **исчез `.git`, рабочее дерево цело** | среда не сохраняет служебные пути git между сессиями | не рассчитывать на локальный клон как на данность: перед работой `git rev-parse --git-dir`, при пропаже — переклонировать (свой протокол: свежий клон и так обязателен перед пушем) |
| тест идёт против чужих данных | осиротевший `fake_cdp.cjs` держал порты, новый не стартовал | проверка портов перед стартом; убивать только свои инструменты по точному пути |
| `run_tests.sh` поднимает `fake_cdp` дважды | скрипт запускает фейк на 9231/9232, и `TestCdpClient` поднимает свой на тех же портах → `EADDRINUSE` в каждом прогоне; проверка готовности удостоверяет «порт занят», а не «наш процесс жив» | один владелец фейка; после `wait_port` проверять `kill -0 $PID` и строку `listening` в логе |
| `pkill -f` убил вызывающую оболочку | шаблон совпал с самой командой | убивать по PID, не по `-f` шаблону |

## Git и remote

| Симптом | Причина | Правило |
|---|---|---|
| пуш отклонён, хотя «то же самое» | локальные коммиты имели ту же суть, но другие SHA, чем на remote | перед пушем: свежий клон + `merge-base --is-ancestor`; сверять содержимое, а не историю |
| риск потерять чужую работу | в `master` лежала другая версия того же каталога | сначала сравнить (файлы и содержимое), потом пушить; старое остаётся в истории |
| «запушено» на словах | проверка только локальная | истина — `ls-remote`/свежий клон |
| `.gitignore` написан, а `git check-ignore` говорит «не игнорируется» | файл уже в индексе: ignore на отслеживаемые не действует, и `check-ignore` это отражает | сначала `git rm -r --cached <путь>`, потом проверять; файл на диске при этом остаётся |
| пуш-скрипт сверял remote с зашитым `BASE=88469d2` | база устарела в тот же день, когда её зашили | `BASE` брать с `ls-remote`, а fast-forward проверять через `merge-base --is-ancestor` |
| конфлюентный пуш | `--force` «чтобы прошло» | force-push запрещён; только fast-forward |
| секрет утёк в файлы | токен писался в URL/конфиг | токен — только в переменную окружения одной командой + inline credential helper; после пуша скан следов и отзыв токена |

## Логика агента

| Симптом | Причина | Правило |
|---|---|---|
| `[архив]` 71.6 % шагов — пустые касты | игнор GCD (obs[8]) | маска способностей при кулдауне |
| `[архив]` обучение падало на первом апдейте на GPU | `brain.h.copy()` — метод numpy, а не тензора | общий интерфейс состояния (`state_copy`/`restore_state`) + негативный контроль в тесте |
| агент «играет» не с той вкладкой | выбиралась первая по URL, а не живая | проба `window.__game.sim` и живая сущность игрока |
| неизвестный навык = тишина | канон навыков подменялся заглушкой | один источник истины (`SkillIndex`); неизвестный навык → исключение |
| мост «молчит» вместо отказа | незапортированная часть отвечала пустым успехом | неготовый бэкенд отвечает 500 и объясняет, что делать (`BRIDGE-PORT`) |
| агент бесконечно зовёт заведомо провальный навык | нет памяти об отказах | `FAIL_LIMIT=3` провала → `FAIL_COOLDOWN=60` решений вне выбора; `LOOP_THRESHOLD=6` повторов → принудительно другое действие |

## woof-ts: среда, сборка, процессы (2026-09-18)

| Симптом | Причина | Правило |
|---|---|---|
| `esbuild: not found`, `dist/` пуст — на ровном месте | песочница стирает `node_modules` и между ходами, и **внутри** хода | любой блок со сборкой/прогоном начинать с `bash tools/setup_game.sh`; не принимать это за баг кода |
| `tsc` «чист», а код не собирается | прогон был вида `tsc --noEmit \| grep '^src/'`: пустой grep при отсутствии `node_modules` выглядит как успех | проверять **код возврата** (`tsc --noEmit` в `set -e`), а не отфильтрованный вывод; это теперь шаг `check_all.sh` |
| синхронное чтение pipe мира падает с `EAGAIN` | libuv переводит pipe в неблокирующий режим; `fs.readSync` для pipe в Node не поддержан | процессом мира владеет воркер, обмен через `SharedArrayBuffer` + `Atomics.wait/notify` |
| `Atomics.wait` висит до таймаута после смерти мира | `notify` был на другом индексе, чем `wait` | будить по тому же индексу, что и ожидание; смерть процесса и переполнение буфера — тоже будят |
| в общий буфер попала мусорная строка | `Buffer.from(typedArray, offset, length)` игнорирует offset/length и копирует весь view | нужен `subarray(offset, offset+length)` |
| тесты убиты сигналом (137) на машине с 2 ГБ | витест с `pool:'threads'` держал несколько живых процессов мира | миры закрывать в `finally`, `fileParallelism:false`, `maxWorkers:1` |
| `Test Files failed (5)` без единого имени теста | кастомный reporter в vitest 4 не печатает детали при падении файла | запускать `npx vitest run` без кастомного reporter'а, чтобы увидеть ошибку |
| `run.mjs` вернул 1, а прогон на самом деле состоялся | код возврата 1 означает и «не было убийств», и «мир упал» | мерить результат по наличию evidence и строке `SUMMARY`, а не по коду возврата |
| тюнинг «нашёл» порог, который на длинной дистанции хуже | скор считается на бюджете `--steps`, а результат от бюджета зависит (при 60 шагах осторожность выигрывает, при 150 — проигрывает) | `--steps` фиксируется в `best.json` и в отчёте; сравнивать можно только прогоны одного бюджета |
| кандидат тюнинга падал с «порог вне диапазона», но подбор шёл дальше | значение из сетки выходило за объявленный `[min, max]` (`PARAM_SPECS`) | сетка строится с учётом границ (`clampToRange`), а выход за границы — исключение в `loadParams`, а не молчаливое округление |

## woof-ts: наблюдение и логика агента (2026-09-18)

| Симптом | Причина | Правило |
|---|---|---|
| `kills=0` за бриджем при том же коде, что на стенде | `canFightMob(templateId, …)` возвращал `false` для пустого `templateId`, а по проводу вида нет | бой решается по **наблюдаемой** Δуровня (`canFightObservedLevel`), выбор правила — по объявленной возможности `entityTemplates` |
| бой выглядел провальным, хотя урон наносился | успех боя определялся по накопленному урону, которого по проводу нет (`damageCounters=false`) | успех — по убийству, прогрессу квеста или **падению наблюдаемой доли HP цели** (`FARM_HP:…`); ветка работает в обоих транспортах |
| агент 34 раза доходил до одного и того же NPC | провалы выдачи квеста ничему не учили: `ACCEPT_FAILED` не снимал цель | порог `giverFailExhaust` (по умолчанию 3) → `GIVER_EXHAUSTED:<npc>` и вычёркивание из кандидатов |
| за бриджем агент шёл к дальнему NPC и не получал квест | порядок выбора пина зависел от типа цели, а доступность квестов по проводу неразличима | при `questStateApi='observed'` — к ближайшему пину; факт выдачи проверяется `interact`-ом и сверкой, а не угадывается |
| `first_turn_in_step` «нет сдачи» при сданном квесте | поле читалось из счётчика до шага сдачи | читать после каждого шага; единицы `world_steps` объявить и не менять между транспортами (действия × frameSkip) |
| профессиональный квест (`q_prof_*`) увёл агента в бесконечный `DO_OBJECTIVE` | в headless-мире нет сбора и крафта, цель недостижима | кандидат на выдачу — только квест с достижимой целью; недостижимый вычёркивается после провалов |
