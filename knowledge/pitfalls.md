## Данные и конфигурация

| Симптом | Причина | Правило |
|---|---|---|
| `[архив]` «квестов 0» при зелёных тестах | молчаливый фолбэк: таблица оракула не от сборки, а код «подставлял число» | нет молчаливых подстановок; чужая таблица → ошибка с текстом |
| `[архив]` раскладка obs «правильная», а поля читаются не те | длина obs не определяет раскладку однозначно (obs=567 бывает и 48/204, и 28/224) | раскладка — из замера сборки, а не из длины |
| `[архив]` таблица оракула работает «иногда» | одна таблица на все версии игры: 204/214 расходятся со 2-й позиции | таблица привязана к сборке |
| координаты ведут в мёртвого моба | память координат по убитому мобу | живой объект проверяется перед использованием (`SkillExecutor.nearestQuestMob` фильтрует живых) |
| навык зовёт не тот индекс | словарь агента и словарь моста разошлись (`turn_in` против `turn_in_quest`, `sell` против `sell_junk`) | один источник истины — `SkillIndex.SKILLS`, сверка с `tools/ref/actions.cjs` тестом `TestSkillIndex` |

## Устройство вычислений `[архив]`

| Симптом | Причина | Правило |
|---|---|---|
| «в логах GPU, счёт на CPU» | тихий откат при недоступном устройстве | явный запрос недоступного → `RuntimeError` |
| на CPU обучение стало в 13 раз медленнее | `auto` выбрал `edge`-бэкенд на CPU (843 мс/шаг против 62 у scipy) | на CPU — `scipy`, `edge`/`sparse` — для GPU |
| состояние «на GPU», но часть весов на CPU | дефолт `device='cpu'` в сборщике весов и STDP | дефолт `None` → общий резолвер |

## Память, порты и процессы

| Симптом | Причина | Правило |
|---|---|---|
| `curl` падает с кодом 23 | переполнение `/tmp` (tmpfs 993 МБ) | тяжёлое — в `/tmp` только при нужде; полные тарболы не качать |
| снимок workspace обрезан, свежие папки пропали | `/home/user` разросся (>128 МБ) | держать воркспейс компактным, дубли данных удалять |
| **исчез `.git`, рабочее дерево цело** | среда не сохраняет служебные пути git между сессиями | не рассчитывать на локальный клон как на данность: перед работой `git rev-parse --git-dir`, при пропаже — переклонировать (свой протокол: свежий клон и так обязателен перед пушем) |
| тест идёт против чужих данных | осиротевший `fake_cdp.cjs` держал порты, новый не стартовал | проверка портов перед стартом; убивать только свои инструменты по точному пути |
| `run_tests.sh` поднимает `fake_cdp` дважды | скрипт запускает фейк на 9231/9232, и `TestCdpClient` поднимает свой на тех же портах → `EADDRINUSE` в каждом прогоне; проверка готовности удостоверяет «порт занят», а не «наш процесс жив» | один владелец фейка; после `wait_port` проверять `kill -0 $PID` и строку `listening` в логе |
| `pkill -f` убил вызывающую оболочку | шаблон совпал с самой командой | убивать по PID, не по `-f` шаблону |

## Инструменты и гигиена

| Симптом | Причина | Правило |
|---|---|---|
| `[архив]` `train.py --help` падал целиком | `%` в тексте помощи argparse принял как формат (`%o format`) | экранировать `%` как `%%`; help — часть контракта CLI |
| `[архив]` тесты зелёные, а инструмент приёмки падает | `run_checks.sh` проверял у `progress_eval.py` только наличие `--device` в `--help`, а не сам прогон; копия `ability_mask` разошлась с `train.py` | проверять **поведение** программы, а не её справку; одну функцию не держать в двух копиях |
| русский текст в логах java → `?????` | нет `file.encoding=UTF-8` | `JAVA_TOOL_OPTIONS` с UTF-8 во всех скриптах |
| тест падал, не показав причину | тело отказа (HTTP 500) лежит в `errorStream`, а читался `inputStream` | клиент обязан читать тело ошибки; отказ — это данные |
| тест «выбор живой вкладки» всегда проходил | у мёртвой и живой вкладок был одинаковый URL — проверить нечего | фейки обязаны различать проверяемое, иначе тест вырождается |
| тесты искали `PASS` в общем логе | один лог на все тесты, `tail -5` видел чужой вердикт | у каждого теста свой лог, вердикт — из него |
| скрипт-тест затирал отслеживаемые файлы | прогон писал в `outputs/` репозитория | тестовые прогоны — с `--tag`/во временный каталог, потом чистка |
| `[архив]` артефакт не привязан к сборке | в `meta` писали объявленный бюджет и хардкод `obs: 607` вместо измеренных | метаданные артефакта — из замеров прогона; заявленное и фактическое обязаны совпадать |

## Git и remote

| Симптом | Причина | Правило |
|---|---|---|
| пуш отклонён, хотя «то же самое» | локальные коммиты имели ту же суть, но другие SHA, чем на remote | перед пушем: свежий клон + `merge-base --is-ancestor`; сверять содержимое, а не историю |
| риск потерять чужую работу | в `master` лежала другая версия того же каталога | сначала сравнить (файлы и содержимое), потом пушить; старое остаётся в истории |
| «запушено» на словах | проверка только локальная | истина — `ls-remote`/свежий клон |
| `.gitignore` написан, а `git check-ignore` говорит «не игнорируется» | файл уже в индексе: ignore на отслеживаемые не действует, и `check-ignore` это отражает | сначала `git rm -r --cached <путь>`, потом проверять; файл на диске при этом остаётся |
| пуш-скрипт сверял remote с зашитым `BASE=88469d2` | база устарела в тот же день, когда её зашили | `BASE` брать с `ls-remote`, а fast-forward проверять через `merge-base --is-ancestor` |
| конфлюентный пуш | `--force` «чтобы прошло» | force-push запрещён; только fast-forward |
| секрет утёк в файлы | токен писался в URL/конфиг | токен — только в переменную окружения одной командой + inline credential helper; после пуша скан следов и отзыв токена |

## Логика агента

| Симптом | Причина | Правило |
|---|---|---|
| `[архив]` 71.6 % шагов — пустые касты | игнор GCD (obs[8]) | маска способностей при кулдауне |
| `[архив]` обучение падало на первом апдейте на GPU | `brain.h.copy()` — метод numpy, а не тензора | общий интерфейс состояния (`state_copy`/`restore_state`) + негативный контроль в тесте |
| агент «играет» не с той вкладкой | выбиралась первая по URL, а не живая | проба `window.__game.sim` и живая сущность игрока |
| неизвестный навык = тишина | канон навыков подменялся заглушкой | один источник истины (`SkillIndex`); неизвестный навык → исключение |
| мост «молчит» вместо отказа | незапортированная часть отвечала пустым успехом | неготовый бэкенд отвечает 500 и объясняет, что делать (`BRIDGE-PORT`) |
| агент бесконечно зовёт заведомо провальный навык | нет памяти об отказах | `FAIL_LIMIT=3` провала → `FAIL_COOLDOWN=60` решений вне выбора; `LOOP_THRESHOLD=6` повторов → принудительно другое действие |
