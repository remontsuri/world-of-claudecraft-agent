# Протокол приёмки: чем доказываем

Один документ на две линии (Java-бот и коннектом), потому что принцип один:
**объявленный заранее порог + воспроизводимая команда + контроли**.

## 1. Порядок доказательства (обязательный)

1. **Root cause.** Сначала причина, потом правка. Правка без причины не считается.
2. **Тест, который падал.** На каждый баг — проверка, которая его ловит (TDD-дисциплина).
   Тест без бага в истории — не нужен; баг без теста — вернётся.
3. **Проверка в песочнице.** Быстрые наборы, без игры и без GPU.
4. **Приёмка на живом.** Реальная игра / реальная карта. Главный пункт.

## 2. Java-линия: что считаем закрытым

| Уровень | Команда | Успех |
|---|---|---|
| Сборка | `bash tools/build.sh` | `build ok -> ... (28 files)` |
| Тесты | `bash tools/run_tests.sh` | `tests passed=3 failed=0` |
| Контракт | внутри тестов | неизвестное действие не исполнено, `idx` дошёл, неготовый бэкенд честно упал |
| Сквозной e2e | `bash tools/run_e2e.sh` | `УСПЕХ: квест сдан обоими путями (Node-мост и Java-мост), нарушений контракта нет` |
| Живая игра | `BridgeMain` + `VoyagerAgent --steps 200` | `[Agent] SUMMARY` с `quests_done ≥ 1` |

Эталон последнего прогона e2e (2026-09-17): `steps=120 kills=3 deaths=0 quests_done=1 first_turn_in_step=8`.
Числа контрольные: сравнение идёт с ними, а не с воспоминаниями.

## 3. Fly-линия: метрики и контроли

Пороги объявлены заранее и **не меняются после замера**:

| Метрика | Порог | Что значит |
|---|---|---|
| M0 | взята: `39.47`, 1 квест, шаг 724 | агент вообще играет |
| M1 | `lvl ≥ 2` | выходит из стартового уровня |
| M2 | `kills ≥ 10` | устойчивый бой |
| M3 | `quests ≥ 5` за эпизод | цепочка квестов (в опенсорсе не показал никто) |
| M4 | `travel ≥ 2.0` | осмысленное перемещение |

Контроли (те же сиды, те же входы): `our` / `rewired` / `er` / `MLP` / `silenced` / `untrained`.
Если контроль не хуже нашего варианта — вывод «эффекта нет» публикуется как результат.

Как запускать по ступеням (нужна машина с игрой и GPU):
`tools/accel_m1_m3.sh` = check → smoke(20) → probe(300) → main(3000),
флаги `--policy fly --max-steps 1200 --no-bench --mask-abilities --oracle-obs --oracle-shaping 0.05`.

## 4. Что проверяется автоматически (и где это запускать)

| Набор | Где | Что ловит |
|---|---|---|
| `fly-woc/tools/run_checks.sh` | песочница | 6 блоков: контроли топологии, таблицы оракула, раскладка obs, компиляция, устройство, GPU-чек |
| `fly-woc/tools/test_device.py` | песочница | строгость выбора устройства, эквивалентность бэкендов схемы, отсутствие скрытого CPU-состояния, детерминизм, память, связка Runner |
| `fly-woc/tools/test_control_graph.py --full` | песочница | rewired/ER на полной схеме (степени, петли, веса) |
| `woof-agent/tools/run_tests.sh` | песочница | контракт моста, выбор живой вкладки, канон навыков |
| `woof-agent/tools/run_e2e.sh` | песочница | полный цикл агента против полигона |
| `woof-agent/tools/build.sh` | песочница | сборка без Maven |
| `hermes/hooks/selftest.sh` | песочница | хуки: блокируют запреты, разрешают обычное, отдают валидный JSON |

## 5. Чего НЕ считаем доказательством

* «Агент ходит и убивает мобов» — без порогов и контролей это демо.
* Зелёный тест при красном живом прогоне.
* Числа без конфигурации (устройство, батч, версия).
* Единичный удачный запуск (нужно 3 сида).
* Скриншот/лог без команды, которой он получен.
