# Протокол приёмки: чем доказываем

Принцип один: **объявленный заранее порог + воспроизводимая команда + контроли**.
Документ про активную линию — Java-бота (`woof-agent/`). Протокол приёмки fly-линии
(метрики M0–M4, контроли топологии, ступени `accel_m1_m3.sh`) перенесён в архив:
`archive/fly-line/VERIFICATION-fly.md`.

## 1. Порядок доказательства (обязательный)

1. **Root cause.** Сначала причина, потом правка. Правка без причины не считается.
2. **Тест, который падал.** На каждый баг — проверка, которая его ловит (TDD-дисциплина).
   Тест без бага в истории — не нужен; баг без теста — вернётся.
3. **Проверка в песочнице.** Быстрые наборы, без игры и без браузера (фейки моста и CDP).
4. **Приёмка на живом.** Реальная игра. Главный пункт.

## 2. Java-линия: что считаем закрытым

| Уровень | Команда | Успех |
|---|---|---|
| Сборка | `bash woof-agent/tools/build.sh` | `build ok -> ... (28 files)` |
| Тесты | `bash woof-agent/tools/run_tests.sh` | `tests passed=3 failed=0` |
| Контракт | внутри тестов | неизвестное действие не исполнено, `idx` дошёл, неготовый бэкенд честно упал |
| Сквозной e2e | `bash woof-agent/tools/run_e2e.sh` | `УСПЕХ: квест сдан обоими путями (Node-мост и Java-мост), нарушений контракта нет` |
| Живая игра | `BridgeMain` + `VoyagerAgent --steps 200` | `[Agent] SUMMARY` с `quests_done ≥ 1` |

Эталон последнего прогона e2e (2026-09-17): `steps=120 kills=3 deaths=0 quests_done=1
first_turn_in_step=8`. Числа контрольные: сравнение идёт с ними, а не с воспоминаниями.

Пересмотрено 2026-09-18 после архивации fly-линии: сборка, тесты и e2e зелёные
(`build ok (28 files)`, `passed=3 failed=0`, обе фазы `turn_in=1 quests_done=1`).

## 3. Контроли для Java-линии

Порог «бот играет» сам по себе слаб: его может дать и заглушка. Поэтому каждое утверждение
про поведение проверяется против контроля **в том же стенде**:

| Утверждение | Контроль | Чем запускаем |
|---|---|---|
| агент сдаёт квест | тот же стенд с выключенной арбитрацией (случайный навык из разрешённых фазе) | `run_e2e.sh` + вариант агента; `quests_done` обязан упасть до 0 |
| гейты фаз работают | тот же прогон без `PHASE_ALLOWED` | нарушения контракта в `/violations` полигона обязаны появиться |
| выбор живой вкладки CDP | фейк с мёртвой вкладкой **первой** и одинаковыми URL был бы вырожденным — поэтому URL разные | `TestCdpClient` |
| канон навыков не разъехался | эталон `tools/ref/actions.cjs` (`applyAction`) | `TestSkillIndex` |
| мост не подменяет успех | неготовый `CdpBackend` обязан отвечать 500 с текстом про `BRIDGE-PORT` | `TestJavaBridge` |

Пока не закрыто (пункты роадмапа): контроль «случайный навык» в e2e — это часть J7/J8,
отдельного запуска сейчас нет.

## 4. Что проверяется автоматически (и где это запускать)

| Набор | Где | Что ловит |
|---|---|---|
| `woof-agent/tools/build.sh` | песочница | сборка без Maven (`javac` + `libs/*.jar`) |
| `woof-agent/tools/run_tests.sh` | песочница | контракт моста, выбор живой вкладки, канон навыков |
| `woof-agent/tools/run_e2e.sh` | песочница | полный цикл агента против полигона: Node-мост и Java-мост |
| `hermes/hooks/selftest.sh` | песочница | хуки: блокируют запреты, разрешают обычное, отдают валидный JSON |

Проверки архивной линии — в `archive/fly-line/TOOLS-fly.md`; в обязательный набор они
больше не входят.

## 4b. woof-ts: приёмка активной линии (2026-09-18)

Одна команда закрывает весь протокол: `bash woof-ts/tools/check_all.sh` → `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`.
Что именно она доказывает:

| Шаг | Чем доказывает | Что считается провалом |
|---|---|---|
| рабочее место | `tools/setup_game.sh` | нет дерева игры, нет сборки, нет `dist-env` |
| типы | `tsc --noEmit` (по коду возврата) | любая ошибка типов; пустой отфильтрованный вывод успехом не считается |
| факты игры | `tools/verify_facts.ts`, `tests/facts.test.ts` | расхождение с деревом игры |
| тесты | `vitest run` (6 файлов, 62 теста, включая 15 на живом env-сервере) | любой красный файл |
| стенд | `run.mjs --seed 42 --steps 150` ×2 | `kills=0`, `quests_done=0`, расхождение двух прогонов (детерминизм) |
| пороги живые | `WOOF_PARAMS` с переопределением + значение вне диапазона | переопределение не печатается; выход за границы не даёт исключения |
| бридж | `build_env.sh` + `run.mjs --transport ndjson --steps 120` | нет evidence, нет `SUMMARY`, `kills=0` |
| контур обучения | короткий `tune.mjs` | нет `learning/history.jsonl`, `best.json`, `last_report.md` или объявления цели в коде |

Быстрые варианты: `SKIP_BRIDGE=1`, `SKIP_TUNE=1` (они же используются, когда проверяется
только правка политики). Пре-коммит хук зовёт тот же скрипт, поэтому «прошло локально»
и «пройдёт в хуке» не расходятся.

Эталоны, с которыми сравнивается прогон (объявлены до замера, seed 42, warrior):

| Мир | Бюджет | world_steps | kills | deaths | quests_done | first_turn_in |
|---|---|---|---|---|---|---|
| стенд `sim` | 150 решений | 4323 | 24 | 22 | 2 | шаг 12 |
| стенд `sim` | 400 решений | 6696 | 31 | 26 | 2 | шаг 12 |
| бридж `ndjson` | 120 решений | 5530 | 2 | 0 | 1 | шаг 6 |

Открытые критерии активной линии: полный квестовый цикл за бриджем (сейчас один квест),
снижение смертей на стенде, робастность по сидам (D6: сид 7 — 1 убийство, 183 смерти).
Итоги подбора порогов — в `woof-ts/learning/last_report.md`, не в этом файле.

## 5. Чего НЕ считаем доказательством

* «Агент ходит и убивает мобов» — без порогов и контролей это демо.
* Зелёный тест при красном живом прогоне.
* Зелёный e2e на фейках вместо живого прогона: фейк доказывает контракт, не игру.
* Числа без конфигурации (версия игры, сборка моста, шаги, сид).
* Единичный удачный запуск (нужно ≥ 3 прогонов/сидов).
* Скриншот/лог без команды, которой он получен.
* Проверка справки CLI вместо проверки поведения программы (так в архивной линии
  проглядели падающий `--mask-abilities`).
