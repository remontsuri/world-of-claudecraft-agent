# World of Claudecraft: что важно знать

Собрано из кода игры (`src/sim/obs.ts`), замеров и прогонов. Числа привязаны к сборкам —
при смене версии игры перепроверяем, а не «переносим по памяти».

## Как запустить офлайн

```
pnpm@10.34.5 → pnpm install --frozen-lockfile → pnpm run dev → http://localhost:5173
→ Play Offline
```

Сид мира — `src/sim/world_seed.ts`. Прогрессия: Eastbrook → Mirefen → Thornpeak →
Farshore / Veiled Hollow.

## Порты и точки

| Порт | Что |
|---|---|
| 5173 | игра (web) |
| 9222 | Chrome DevTools Protocol (существующий браузер, `--remote-debugging-port`) |
| 8791 | мост к игре (Java или Node) |
| 8792 | MCP-сервер агента |
| 9231 / 9232 | фейковый CDP в тестах (HTTP / WS) |

## Раскладка наблюдений (obs)

`obsSize() = 16 + ABILITY_SLOTS*2 + 9 + NEARBY_MOBS*6 + 5 + QUEST_ORDER.length*2 + 3`
при `NEARBY_MOBS = 5`. Ключевые поля, на которых всё ломается:

* **obs[4] / obs[5]** — позиция x / z, нормированная на 900;
* **obs[8]** — `gcdRemaining / GCD`: больше нуля ⇒ способности на кулдауне, каст
  только в очередь (отсюда маска способностей);
* дистанции — `d / 40`, значения до 1.5;
* пары квестов идут как `[state, progress]`, где state: 1 / 0.66 / 0.33 / 0.

**Длина obs+действий однозначно не задаёт раскладку.** obs=567 даёт разные раскладки
при разном числе способностей (например 48 способностей / 204 квеста против
28 / 224). Поэтому раскладка выводится по замеру сборки, а не угадывается по длине:
`obs_layout.configure()` (модуль в архиве: `archive/fly-line/fly-woc/obs_layout.py`).

## Квесты и размер obs по сборкам

| Сборка игры | Область | Квестов | Способностей | obs |
|---|---|---|---|---|
| v0.39.0 | 204 | 204 | 48 | 567 |
| v0.40.x | 214 | 214 | 48 | 587 |
| main / v0.42.2 | 224 | 224 | 48 | 607 |

Числа важны для моста: по размеру obs и числу квестов определяется раскладка полей, а
«угадывание по длине» уже один раз стоило нам «0 квестов при зелёных тестах».

Таблицы оракула (`quest_oracle_204/214/224.json`) и гейт «таблица от этой сборки» лежат
в архиве fly-линии: `archive/fly-line/fly-woc/data/`, `archive/fly-line/fly-woc/quest_oracle.py`.
Правило из той линии остаётся в силе и для Java: чужая версия данных обязана давать ошибку
с текстом, а не «подставим, что есть».

## Границы мира

v0.40 / v0.42: `minX = −540`, `maxX = 540`, `minZ = −180`, `maxZ = 2420`.
Навигация и оракул считают расстояния в этих пределах; выход за них — не «далеко»,
а ошибка данных.

## Мелкие, но важные факты

* `ABILITY_SLOTS = max(abilities.length)` по массиву игрока, `ACTIONS` = 13 базовых + слоты.
* Квестодатели помечены как `questGiverNpcMarkers` в `src/sim/content/`.
* Сервер окружения: `frameSkip 5`, `maxSteps 8000` — то есть один шаг агента
  соответствует нескольким кадрам симуляции, и «пустые касты» в логах (71.6 % шагов
  в замере `archive/fly-line/OFFLINE_PLAY.md`) — прямое следствие игнора GCD.
* Мобы/предметы привязываются к координатам; память координат по **мёртвым** мобам —
  известная ошибка, которая уже стоила нам ложных «иду к цели».
