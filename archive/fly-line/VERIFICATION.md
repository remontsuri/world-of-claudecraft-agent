## 2. Два графа: traced-only и полная таблица

Схема собирается одним и тем же кодом, меняется только входной файл. `build_circuit.py` доработан для стриминговой записи (патч в §7), иначе `sorted()`+один `json.dumps` не помещаются в RAM на миллионах рёбер.

```bash
python3 build_circuit.py /data/malecns        /data/circuit-traced   # traced-only
python3 build_circuit.py /data/full/malecns   /data/circuit-full     # полная таблица
```

| Параметр | traced-only | полная таблица (min-conf 0.5) |
|---|---:|---:|
| файл рёбер | 508 МБ, 25 563 197 строк | 1.05 ГБ, 151 856 684 строки |
| hop1 (рёбра на DN) | 566 870 | 818 956 |
| hop2 (рёбра на P1) | 2 036 783 | 2 715 371 |
| ядро | 8 819 (DN 1314 + P1 4000 + P2 4097) | 8 820 (DN 1314 + P1 4000 + P2 4098) |
| **клеток** | **8 835** | **8 836** |
| **рёбер** | **1 874 865** | **1 874 492** |
| **контактов** | **15 800 512** | **15 798 906** |
| readout DN | 82 (18 принудительных) | 82 (18 принудительных) |
| `circuit.json` | 26.6 МБ, sha `3514c098…` | 26.6 МБ, sha `3d90919e…` |
| сборка | 12.8 с | 58 с, пик RSS 685 МБ |

Регрессия: пересборка traced-схемы из скачанных заново данных даёт файл, **побайтово равный** закоммиченному (`cmp` без различий, sha `3514c09808cc6affaf044aaf7b242b9fe191c2539abd156d534302e42438384c`). Конвейер детерминирован.

### Разрешение терминологической путаницы

В ветке фигурируют три разных числа, и они означают разное:

| Число | Что это |
|---|---|
| 25 563 197 | **все** строки файла `traced-only` (рёбра по всему CNS, включая невошедшие в схему) |
| 151 856 684 | **все** строки полной таблицы min-conf 0.5 |
| 1 874 865 / 1 874 492 | рёбра, которые реально остаются **внутри** DN-центрической схемы (её и видит `fly_brain.py`) |

То есть «26M синапсов вместо 1.8M» — это про размер исходных файлов, а не про схему: в схему отбираются те же ~1.87 млн рёбер.

## 4. Воспроизведение бенчмарка v2 (пункт 4 чеклиста)

Запуск ровно с теми же параметрами, что в README, и с теми же held-out сидами:

```bash
WOC_PYTHON_PATH=<...>/woc-game/python python3 train.py --eval-only --tag v2 --eval-episodes 5 \
  --conditions fly-sampled,fly-silenced,fly-untrained,random \
  --rewards '{"xp": 0.02, "kill": 1.0, "timePenalty": 0.001, "questProgress": 1.0, "questDone": 10}'
```

| Условие | Закоммиченный `benchmark_v2.json` | Мой прогон | Статус |
|---|---|---|---|
| fly-sampled | 23.688 / 23.568 / 23.434 / 2.048 / 23.592 | **то же, 5/5** | ✅ точное совпадение |
| fly-silenced | 1.2 ×5 | 1.2 ×5 | ✅ |
| fly-untrained | 1.2 ×5 | 1.2 ×5 | ✅ |
| random | −4.024 / −4.024 / −3.912 / −6.57 / −3.885 | 1.200 / 3.316 / −3.902 / 1.260 / 1.200 | ⚠️ расходится |
| mean fly-sampled | +19.27 (README) | **+19.266** | ✅ |

Все эпизоды: 1200 шагов, lvl 1, xp 60, 0 смертей, 1 квест (кроме сида 900004: xp 0, 0 квестов — совпадает с оригиналом).

**Почему расходятся только `random`.** Условие `random` берёт действия из `env.action_space.sample()`. В `WoWClassicEnv.reset()` вызывается `super().reset(seed=seed)`, который сидит `np_random` **самого env**, но не пробел действий, а у `Discrete` свой RNG, инициализируемый от энтропии ОС. Проверка: два последовательных создания env с одним и тем же `reset(seed=900001)` дают разные последовательности действий (`[27,51,46,6,25]` vs `[24,8,28,32,21]`).

Отсюда:

- fly-условия воспроизводимы: их действия детерминированы (`torch.manual_seed(args.seed)` + `Categorical(logits).sample()`), а сим детерминирован — поэтому совпадение до третьего знака.
- `random` — невоспроизводимый baseline по построению, а не признак ошибки в конвейере.

Фикс, если нужно сделать `random` воспроизводимым (одна строка в `wow_env.py`):

```python
def reset(self, *, seed=None, options=None):
    super().reset(seed=seed)
    if seed is not None:
        self.action_space.seed(seed)      # + эта строка
        self._episode_seed = seed
```

## 5. Проверка полного графа как замены

Тот же чекпойнт `params_fly_v2.pt` (обученный на traced-схеме), но `data/circuit.json` подменён на полный граф (8 836 клеток):

| Условие | traced-only | полный граф (8836 клеток) | Статус |
|---|---|---|---|
| fly-sampled | 23.688 / 23.568 / 23.434 / 2.048 / 23.592 | **те же 5 чисел** | ✅ |
| fly (greedy) | 1.200 ×5 | 1.200 ×5 | ✅ |
| fly-silenced | 1.200 ×5 | 1.200 ×5 | ✅ |
| fly-untrained | 1.200 ×5 | 1.200 ×5 | ✅ |

Прогонов на полном графе было два, оба дали одинаковый результат: первый (`reference/benchmark_fullgraph.json`, три условия) и расширенный (`reference/fullgraph_eval_extended.log`, fly + fly-sampled + fly-silenced по 5 сидов). Расширенный прогон остановлен осознанно на `fly-untrained`: остальные условия (`mlp`, `mlp-sampled`, `openloop`, `random`) **схему не читают вообще** — в `train.py:241` `FlyBrain` создаётся только для условий `fly*`, а MLP идёт по ветке raw obs (`train.py:274`), поэтому прогонять их на полном графе бессмысленно, числа будут те же по построению.

Вывод: полный граф — drop-in замена, переобучение readout не требуется. После тестов схема возвращена на traced (sha сверен).

## 6. Что осталось (пункты 5–6) и как это сделать

**Пункт 5 — engagement-награды.** Два пути:

*Вариант A (рекомендую, ничего в игре не патчится).* Награды передаются per-reset через Python: `WoWClassicEnv(..., rewards={...})`, что `train.py --rewards '…'` уже и делает (в `env_server.ts` они мержатся в `DEFAULT_CONFIG.rewards` по `reset`). Именно так получены все числа выше — работает без пересборки бандла.

*Вариант B (только если нужен дефолт для других хостов).* Правка `headless/env_server.ts`:

```diff
--- a/headless/env_server.ts

@@ -82,11 +82,11 @@

+    xp: 0.02,
```

## 8. Честные границы этой верификации

1. Воспроизведён **инференс обученных весов**, а не обучение с нуля (600 updates PPO). Для полного воспроизведения обучения нужны твои сиды/бюджеты и часы CPU.
2. Воспроизведён **один training seed** — как и в оригинале; про робастность это ничего не говорит.
3. «Полный граф» здесь = полная **таблица связей** min-conf 0.5, а не полный коннектом: клеток в схеме те же ~8.8 тыс. из 211 577 (схема DN-центрическая по построению).
4. `random`-контроль в песочнице не сверялся (невоспроизводим by construction, см. §4) — это ограничение baseline, не результата.
5. Не проверялось: живая игра (браузер/`D:\woc`), `mlp`-контроль, `openloop`, LIF-режим из `src/fly_brain`.
