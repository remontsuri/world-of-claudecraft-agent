# Коннектом MaleCNS и наша схема

## Что за данные (и как их цитировать)

* **MaleCNS v1.0** — полный коннектом самца дрозофилы: ~166 700 нейронов, ~125 млн синапсов.
* Данные опубликованы **8 июня 2026** (male-cns.janelia.org), статья — **Cell, 3 сентября 2026**.
* Авторство: FlyEM / Janelia, Cambridge, MRC LMB, Google Research.
* Лицензия данных — **CC BY 4.0**: атрибуция обязательна в производных артефактах, фигурах, отчётах.
* Bulk-данные: `gs://flyem-male-cns/v1.0/connectome-data/flat-connectome/` (4 обязательных feather).

Частая ошибка в пересказе: «MaleCNS выпущен 3 сентября» — неверно, 3 сентября вышла статья,
данные — 8 июня.

## Наша рабочая схема `fly-woc/data/circuit.json`

| Параметр | Значение |
|---|---|
| Узлов | 8835 |
| Рёбер | 1 874 865 |
| Входов / выходов (DN) | 52 / 82 |
| Каналов | 13 |
| Вес ребра | счётчик контактов 1…1601 (**все положительные**) |
| Знак | берётся у **пресинаптического** нейрона (`sign[pre]`) |
| Дубли пар | 0 |
| Петли | 7 |
| Макс. out-degree | 3088 |

Следствие: «36 % рёбер не согласованы со знаком узла» — не ошибка, а свойство формата:
знак живёт в узле, а не в ребре. Контроль обязан это сохранять, иначе он контролирует
не то.

Нормализация входа (как в Fly Dino): `W[j,i] = c · sign[i] / Σ_k c · |sign[k]|` по
входящим рёбрам постсинаптической клетки; нулевой знаменатель → 0.

## Динамика: что есть и что планируется

Сейчас в активной линии (`fly-woc/fly_brain.py`) — leaky-tanh:
`h = (1−leak)·h + leak·tanh(u + gain·rec)`, 3 итерации, выход `4·h[DN]`.

LIF, который переносим (наш же, `src/fly_brain/engine.py`, conductance-модель):

| Параметр | Значение |
|---|---|
| `tauSyn` | 5.0 мс |
| `tDelay` | 1.8 мс |
| `tauMem` | 10.0 мс |
| `tRefrac` | 2.0 мс |
| `vRest` / `vReset` | −65 мВ |
| `vThreshold` | −50 мВ |
| `dt` | 0.2 мс (внутренний шаг симуляции) |

Референс для сверки динамики сторон: `flybrain` (PyPI, MIT, alextitonis/fly.ai) —
LIF по всему коннектому, batch, `dt ≈ 2 мс`, рефрактерность; сравнение — по
**статистике активности DN на одном и том же входе**, критерий и допуск объявляем заранее.

## Контроли топологии (уже сделаны)

`tools/make_control_graph.py`:

* `--mode degree` — обмен рёбер (double edge swap): in/out-степени каждого узла
  сохраняются **точно**, граф простой, вес остаётся на своём ребре. На полной схеме
  при 25 % обменов изменилось 39.4 % пар, петли 7 → 7.
* `--mode er` — Эрдёш–Реньи с теми же N и M, петли исключены, мультимножество весов то же:
  100 % пар изменено, петли 7 → 0.

Слепая тасовка хвоста (первая версия) — **тупик**, падала на 110 из 400 рёбер; не возвращаться.

## Абляции и что они значат

Уже поддержаны: `silenced` (схема выключена), `untrained` (без обучения читаута),
`our` (наша схема), `rewired` (степени сохранены), `er` (случайный граф), `MLP`
(на тех же входах). Приёмка — по 3 сидам, пороги объявляются заранее.

## Внешние ориентиры (кто что показал)

* **FlyDoom** (Wormuth): дофаминовый контур на урон, стримы; в README сами пишут
  «learned survival has not been demonstrated». Лицензии нет → берём только схему эксперимента.
* **FLYT3**: их же негативный контроль — MLP на тех же входах 85.7 % против коннектома 60.8 %.
  Значит, вопрос «коннектом лучше MLP?» зададут первым.
* **FalinX/fly-brain**: ridge-readout поднял попадание 66.6 → 78.5 %, но игру сделал **хуже** —
  читаут был обучен на состояниях другого контроллера. Вывод для нас: не смешивать
  пары «энкодер + читаут» между версиями и контроллерами.
* **fly-craftax** (MIT): дисциплина `make eval / controls`, калибровка, проверка против
  внешнего эталона (Shiu et al.), обязательные абляции.
* **neuroterrarium**, **FlyPong**: отрицательные результаты по топологическому контролю —
  если у нас выйдет так же, это результат, а не провал.
