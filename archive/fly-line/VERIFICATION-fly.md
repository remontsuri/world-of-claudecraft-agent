# Протокол приёмки fly-линии (в архиве)

Вынесено из `knowledge/verification.md` 2026-09-18 при архивации линии. Пути даны **до**
переноса; после него добавь префикс `archive/fly-line/`.

## Метки и контроли

Пороги объявлены заранее и **не меняются после замера**:

| Метрика | Порог | Что значит |
|---|---|---|
| M0 | взята: `39.47`, 1 квест, шаг 724 | агент вообще играет |
| M1 | `lvl ≥ 2` | выходит из стартового уровня |
| M2 | `kills ≥ 10` | устойчивый бой |
| M3 | `quests ≥ 5` за эпизод | цепочка квестов (в опенсорсе не показал никто) |
| M4 | `travel ≥ 2.0` | осмысленное перемещение (метрика признана непригодной: у мёртвых политик значение выше, чем у живой) |

Контроли (те же сиды, те же входы): `our` / `rewired` / `er` / `MLP` / `silenced` / `untrained`.
Если контроль не хуже нашего варианта — вывод «эффекта нет» публикуется как результат.

Ступени (нужна машина с игрой и GPU): `tools/accel_m1_m3.sh` = check → smoke(20) →
probe(300) → main(3000), флаги `--policy fly --max-steps 1200 --no-bench --mask-abilities
--oracle-obs --oracle-shaping 0.05`.

## Что проверялось автоматически

| Набор | Что ловил |
|---|---|
| `fly-woc/tools/run_checks.sh` | 8 блоков: контроли топологии, таблицы оракула (+ паритет на 4000 наблюдений), раскладка obs, компиляция, устройство, параллельные среды, GPU-чек |
| `fly-woc/tools/test_device.py` | строгость выбора устройства, эквивалентность бэкендов схемы, отсутствие скрытого CPU-состояния, детерминизм, память, связка Runner |
| `fly-woc/tools/test_control_graph.py --full` | rewired/ER на полной схеме (степени, петли, веса) |
