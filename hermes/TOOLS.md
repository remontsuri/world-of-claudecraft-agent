# Инструменты: что, когда, с каким ожидаемым результатом

Правило: **команда → ожидаемая строка успеха**. Если строка другая — это не «мелкий шум»,
а сигнал; сначала разобраться, потом продолжать.

## Перед началом работы (30 секунд, дешёвый предохранитель)

```bash
git fetch --all && git log --oneline -3 origin/master   # где мы на самом деле
ss -ltnp | grep -E '8791|9231|9232'                     # не заняты ли порты чужими процессами
```

Ожидаемо: ветка совпадает с тем, что делаем; порты свободны либо заняты нашими
инструментами. Чужой процесс на этих портах — стоп и сообщение пользователю.

## Java-бот (активная линия)

| Когда | Команда | Успех |
|---|---|---|
| после любой правки | `bash woof-agent/tools/build.sh` | `build ok -> ... (28 files)` |
| после любой правки | `bash woof-agent/tools/run_tests.sh` | `tests passed=3 failed=0` |

| живой прогон (машина с игрой) | `BridgeMain` + `VoyagerAgent --steps 200` | `[Agent] SUMMARY ... quests_done ≥ 1` |

e2e — единственная проверка, которая прогоняет весь цикл (мост → агент → квест).
Его нельзя «ускорить» частичным прогоном: он и есть приёмка.

## Проверка, которая спасает от глупого пуша

```bash
# перед push: свежий клон + предок + сверка содержимого
git -C /tmp/pushrepo merge-base --is-ancestor origin/backup HEAD && echo fast-forward
git -C /tmp/pushrepo diff --stat origin/backup HEAD | tail -1
```

Ожидаемо: `fast-forward` и diffstat только с нашими изменениями. Если предок не
подтверждается — **не пушить**, а разбираться: скорее всего, локальная история
разошлась с remote (у нас так и было: та же суть, другие SHA).

## Что запускать НЕ надо

* `mvn` / `gradle` — проекта на Maven нет, сборка на `javac`.
* Перезапуск игры/браузера «чтобы применились правки» — запрещено.
* Проверки и тренировки из `archive/fly-line/` — архив, не рабочая линия.
* Скачивание тяжёлых данных коннектома (MaleCNS, >100 МБ) без явного подтверждения.
* `git push --force` — никогда, ни при каких «а у меня не пушится».
