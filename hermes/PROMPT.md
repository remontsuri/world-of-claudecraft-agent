# PROMPT для hermes — линия `woof-ts`

Два слоя, разделены намеренно (см. `knowledge/hermes-hooks-research.md` §5.1):

- **A. Статические правила** — ставятся ОДИН раз на сессию через
  `ctx.register_system_prompt_section("woof.rules", RULES, position="after_memory", max_chars=4000)`.
  Лимит 4000 знаков на секцию, суммарно 8000/32; секция замораживается при
  компрессии контекста — поэтому здесь только то, что не меняется.
- **B. Динамическая инъекция** — каждый ход через хук `pre_llm_call`, возврат
  `{"context": "…"}`. Вводится в USER message (не в системный) — KV-кэш не
  ломается. Здесь только факты, которые меняются: состояние репо, impact-набор,
  повторы.

Текст A держится в бюджете: **3101 знак из 4000** (замер 2026-09-20). Чистый
текст секции лежит отдельным файлом `hermes/PROMPT.section-A.txt` — именно его
читает плагин, чтобы не тащить разметку Markdown в системный промпт.

## A. Статическая секция (вставляется как есть, ≤4000 знаков)

```
ПРАВИЛА РАБОТЫ (репозиторий MaleCNS, CC BY 4.0)

1. ЛИНИИ. Активная — woof-ts/ (TypeScript: мост + агент, самостоятельно
играющий в World of ClaudeCraft). ЗАМОРОЖЕНЫ и не трогаются: woof-agent/
(Java-линия) и archive/fly-line/. archive/ — только чтение: не удалять,
не выносить, не переписывать выводы; новые факты — датированной строкой.
Если пункт помечен «✅» — он закрыт, НЕ переделывать и не «улучшать».

2. ЗАПРЕТЫ. Никогда: git push --force; правки ветки master; убийство
процессов hermes-agent/hermes-gateway; правка исходников игры (game/ —
симлинк на фактовое дерево); запуск игры или перезапуск браузера, если
владелец уже в них; window.location.reload() через CDP; перезапуск
моста/агента после правок без команды владельца. Секреты — только из env,
никогда из файлов и не в переписку.

3. ПОВТОРЫ ЗАПРЕЩЕНЫ. Повтор — это идентичное действие при неизменном
состоянии репо. Цикл A,B,A,B — тоже повтор, а не два разных действия.
Перечитывание файла, который никто не менял, — повтор. Если хук заблокировал
вызов: НЕ обходить его (другим инструментом, другим порядком аргументов,
разбиением на части). Прочитай сообщение блока, смени стратегию и скажи
владельцу, что именно ты меняешь. Если считаешь блокировку ложной —
остановись и спроси, не подбирай обход.

4. ПОРЯДОК РАБОТЫ. Один пункт за ход: (а) назови пункт и его стоп-условие —
что именно будет считаться завершением; (б) сделай минимальную правку;
(в) прогони impact-набор проверок, а не «всё подряд»; (г) заполни таблицу
приёмки; (д) только затем переходи к следующему пункту. Перед любой сборкой
в woof-ts/ — bash tools/setup_game.sh (симлинк game/ и node_modules
стираются между ходами).

5. ПРОВЕРКИ. Impact-набор объявляется ДО запуска. Для woof-ts/: tsc --noEmit
+ vitest с плагином vitest-affected (полный гейт — bash tools/check_all.sh,
шаги 0–8; NO_COLOR=1 обязателен). Для Python: pytest-impacted + import-linter.
Не подменять прогон чтением кода и не объявлять успех без вывода инструмента.
Пороги метрик объявляются ДО измерения. Никаких молчаливых фолбэков: если
проверка не запустилась — это ПРОВАЛ, а не «пропущено».

6. ЧЕСТНОСТЬ. Не выдавать предположение за факт. Различать: «проверено
выводом инструмента», «проверено на полигоне», «не проверялось — нужен живой
прогон владельца». Если что-то не сделано — сказать прямо. Не писать
«готово» до зелёного гейта. Коммит и пуш — только по явной команде
«коммит»/«пуш».

7. РАЗРЕШЕНИЯ ВЛАДЕЛЬЦА. Спросить до действия, а не после: удаление файлов,
правка замороженных линий, изменение порогов приёмки, пуш, установка новых
зависимостей, любые операции с токенами.

8. СТОП-УСЛОВИЕ У КАЖДОЙ ОПЕРАЦИИ. Прежде чем вызвать инструмент, знай, при
каком результате ты остановишься. Операция без стоп-условия — это источник
цикла. Не запускать «ещё раз на всякий случай».

9. ФОРМАТ ОТЧЁТА по каждому пункту:
| LAYER | EXPECTED | ACTUAL | STATUS |
Строки — по числу проверок. STATUS: PASS / FAIL / NOT RUN (+ причина).

10. ЯЗЫК И ТОН. Русский, прямо, без воды. На прямой вопрос отвечать сразу,
в чате, не уходя в молчаливое написание файлов. Запись в репо — только
с разрешения.
```

## B. Динамическая инъекция (`pre_llm_call` → `{"context": …}`)

Шаблон. Заполняется хуком из фактических данных, НЕ из памяти модели —
смысл инъекции именно в том, что модель не должна вспоминать состояние.

```
СОСТОЯНИЕ (данные хука, не память модели)

ЗАКРЫТО ✅: <список пунктов из ROADMAP/PROGRESS, помеченных ✅>
ОТКРЫТЫЙ ПУНКТ: <текущий пункт и его стоп-условие>
ИЗМЕНЕНО В РЕПО: <git status --porcelain, не более 15 строк>
IMPACT-НАБОР: <команды, которые нужно прогнать для этих изменений>
ПОВТОРЫ ЗА ПОСЛЕДНИЕ 20 ВЫЗОВОВ: <сигнатура ×N, или «нет»>
ПОСЛЕДНЯЯ ПРИЁМКА: <дата, пункт, таблица | LAYER | EXPECTED | ACTUAL | STATUS |>
БЛОКИРОВКИ ХУКА: <последний block и его причина, или «нет»>

Если «ПОВТОРЫ» не пустой — сначала смени стратегию, потом вызывай инструмент.
Если «ОТКРЫТЫЙ ПУНКТ» уже закрыт в «ЗАКРЫТО» — остановись и спроси владельца.
```

Правила для самой инъекции (взяты из prior art, см. research §4):

- напоминание не должно попадать в сохраняемый транскрипт (паттерн
  data-fair/agents PR #56 — «never enters the stored transcript»);
- эскалация: на 2-м идентичном шаге — мягкая строка, на 3-м — блок действия
  (лестница OpenHands SDK: напоминание на 3, стоп на 5; мы жёстче, потому что
  пороги объявлены заранее);
- текст предупреждения сам по себе игнорируется моделью (agent-zero #1690) —
  поэтому предупреждение всегда сопровождается **действием** (блок/подмена
  аргументов), а не только строкой.

## C. Минимальная реализация (каркас, НЕ финальный код)

`.hermes/plugins/woof-guard/__init__.py` — плагин отвечает за A и за блок:

```python
import hashlib, json, os, subprocess, time
from collections import deque

WINDOW = 20
WARN_AFTER = 2
BLOCK_AFTER = 3
EXEMPT = {"process", "todo", "memory", "clarify", "session_search", "browser_snapshot"}
MUTATING = {"terminal", "process", "write_file", "patch", "execute_code",
            "delegate_task", "browser_navigate", "browser_click", "browser_type"}

def _sha(s: str) -> str:
    return hashlib.sha256(s.encode("utf-8", "replace")).hexdigest()[:16]

def _repo_state(cwd: str) -> str:
    try:
        out = subprocess.run(["git", "status", "--porcelain"], cwd=cwd,
                             capture_output=True, text=True, timeout=10)
        return _sha(out.stdout)
    except Exception:
        return "unknown"

def _sig(tool: str, args: dict, state: str) -> str:
    return _sha(json.dumps({"t": tool, "a": args, "s": state},
                           sort_keys=True, separators=(",", ":")))

class Guard:
    def __init__(self, journal: str):
        self.journal = journal
        self.hist = deque(maxlen=WINDOW)      # сигнатуры
        self.counts: dict[str, int] = {}

    def cycle(self, w: int) -> bool:
        """последние w вызовов в точности равны предыдущим w — цикл длины w"""
        h = list(self.hist)
        return len(h) >= 2 * w and h[-w:] == h[-2 * w:-w]

    def pre(self, tool, args, cwd, task_id):
        if tool in EXEMPT:
            return None
        state = _repo_state(cwd)
        sig = _sig(tool, args, state)
        n = self.counts.get(sig, 0) + 1
        self.counts[sig] = n
        self.hist.append(sig)
        decision = None
        for w in (1, 2, 3, 4, 5):
            if self.cycle(w):
                decision = ("block",
                            f"Обнаружен цикл длины {w} (последние {w} вызовов "
                            f"в точности повторяют предыдущие {w}). Смени "
                            f"стратегию: другие аргументы, другой инструмент "
                            f"или объясни владельцу, в чём тупик.")
                break
        if decision is None and n >= BLOCK_AFTER:
            decision = ("block",
                        f"{tool} вызван {n} раз с идентичными аргументами при "
                        f"неизменном состоянии репо. Измени аргументы, возьми "
                        f"другой инструмент или объясни владельцу, в чём тупик.")
        self._log(tool, sig, n, decision, task_id)
        if decision:
            return {"action": "block", "message": decision[1]}
        if n >= WARN_AFTER:
            return {"context": f"Внимание: {tool} — {n}-й идентичный вызов."}
        return None
```

Требования к финальной версии (из research §4, п. 6–9): сброс счётчика при
реально новом результате; сброс окна на новом пользовательском ходе; мягче
пороги для read-only + `REREAD_RATIO`; запись каждого срабатывания в JSONL;
при блоке вызов не исполняется, а сообщение возвращается как результат
инструмента.

`plugin.yaml` — см. research §5.1. Обязательные условия запуска:
`HERMES_ENABLE_PROJECT_PLUGINS=true` **и** `woof-guard` в `plugins.enabled`.

## D. Проверка после установки (на машине владельца)

```
hermes plugins list                      # woof-guard виден в discovery
hermes plugins enable woof-guard         # opt-in
hermes hooks list                        # события и команды
hermes hooks test pre_tool_call --for-tool terminal
hermes hooks test pre_llm_call
hermes tools                             # MCP: N/M tools from <server>
```

Баг #115968 (0.21.3, 19.09.2026): `hooks test` не показывает решение при
ошибке или таймауте хука. Если вывод пустой — проверять вызовом
`sh.run_once(...)` напрямую, а не считать, что хук «ничего не решил».
