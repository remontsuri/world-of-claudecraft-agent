# Инструкции для hermes

Этот каталог — то, что агент-исполнитель (hermes) обязан прочитать и соблюдать, чтобы
не терять главное между сессиями. Здесь же — инструменты, которые он запускает, и
хуки, которые не дают забыть про проверки и правила.

## Порядок чтения (в начале каждой сессии)

1. `AGENTS.md` (корень) — стоячие правила проекта: что можно и что нельзя.
2. `knowledge/principles.md` — как думать: доказательства, контроля, отсутствие тихих откатов.
3. `knowledge/pitfalls.md` — грабли; минимум по диагонали, чтобы не наступить заново.
4. `woof-agent/ROADMAP.md` — где мы сейчас и что закрыто с проверкой.
5. `hermes/skills/woc-master-goal/SKILL.md` — главная цель и инварианты.

## Главное в трёх строках

* Активная линия — **автономный Java-бот** в `woof-agent/` (мост к игре, навыки, квесты).
* Fly-линия (коннектом) — **архивирована 2026-09-18** в `archive/fly-line/`: не трогаем и не
  запускаем её проверки без явной задачи «разморозить».
* Любое утверждение подтверждается командой из `hermes/TOOLS.md`, а не памятью.

## Что hermes делает сам, а что — только с разрешения

| Действие | Разрешение |
|---|---|
| Читать код/доки, гонять тесты и e2e, писать файлы в репозитории | сам |
| Коммит в локальную ветку | сам |
| `git push` | только в разрешённые ветки (см. `AGENTS.md`), без `--force` |
| Запуск/остановка игры, браузера, мостов | только по явной команде пользователя |
| Убийство процессов `hermes-agent` / `hermes-gateway` | **никогда** |
| Правка исходников игры (`D:\woc`) | **никогда** |
| Скачивание тяжёлых данных коннектома (MaleCNS, `.feather`, >100 МБ) | только с явным подтверждением |

## Цикл работы, который от него ждут

1. **Понять задачу** и найти её в `ROADMAP.md`. Нет в роадмапе — сначала записать туда.
2. **Воспроизвести** текущее поведение командой (лог — в артефакт, а не «по памяти»).
3. **Найти причину**, а не симптом; правку начинать с падающей проверки.
4. **Прогнать** `hermes/TOOLS.md` → «после правок».
5. **Записать** результат: обновить `ROADMAP.md`, при новом знании — `knowledge/`,
   при новом поведении — `woof-agent/ARCHITECTURE.md`.
6. **Пушить** только то, что прошло проверки; иначе — оставить локально и сказать, что не так.

## Формат отчёта (тот, что уже принят в проекте)

Таблица `LAYER | EXPECTED | ACTUAL | STATUS` плюс путь к артефакту (лог, файл, коммит).
Без таблицы и без команды-подтверждения отчёт не принимается.
