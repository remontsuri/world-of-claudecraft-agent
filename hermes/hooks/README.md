# Хуки для hermes: чтобы не терять главное

Три хука, которые закрывают три реальные потери: «забыл правила», «сломал запрет»,
«забыл записать результат».

| Хук | Когда | Что делает |
|---|---|---|
| `session_start.sh` | старт сессии | печатает цель, инварианты, текущие незакрытые пункты роадмапа, состояние branch/портов |
| `guard.sh` | перед опасным действием (команда/запись файла) | блокирует `--force` push, убийство `hermes-agent`/`hermes-gateway`, правку исходников игры, коммит тяжёлых файлов |
| `task_end.sh` | конец задачи | прогоняет релевантные проверки, напоминает обновить `ROADMAP.md` / `knowledge/`, ищет незаписанное |

## Контракт

**stdin** — JSON-событие:

```json
{"event": "session_start|pre_tool|task_end",
 "cwd": "/path/to/repo",
 "tool": "Bash|Edit|Write",
 "command": "git push --force origin master",
 "paths": ["woof-agent/tools/run_tests.sh"],
 "task": "короткое описание задачи"}
```

**stdout** — JSON-ответ:

```json
{"continue": true, "message": "текст, который агент увидит"}
```

`continue: false` — действие запрещено, `message` объясняет причину и что делать вместо.
Ненулевой код возврата у `guard.sh` — тоже блокировка (для строгих интеграций).

Скрипты работают и вручную:

```bash
echo '{"event":"pre_tool","command":"git push --force"}' | bash hermes/hooks/guard.sh; echo "код: $?"
bash hermes/hooks/session_start.sh
```

## Проверка самих хуков

```bash
bash hermes/hooks/selftest.sh     # ожидаем: хуки: passed=12 failed=0 → ВСЁ ЗЕЛЁНОЕ
```

Самотест проверяет и блокировки (force-push, убийство hermes-agent, правка игры,
коммит тяжёлых файлов), и разрешения (обычный push, тесты), и валидность JSON
у напоминаний. Хуки — часть контракта, значит проверяются как код.

## Windows

Обёртки для случаев, когда hermes запускает команды через `cmd.exe`:
`hermes/hooks/win/{session_start,guard,task_end}.cmd`. Внутри — те же bash-скрипты
(нужен Git for Windows). Если `bash` не найден, обёртка не блокирует агента, а честно
сообщает, что предохранитель не активен: правила всё равно описаны в `AGENTS.md`,
и молчаливая блокировка работы была бы хуже.

## Регистрация

Формальная схема регистрации зависит от конфигурации hermes — шаблон в `hooks.json`
описывает ожидаемые события и пути к скриптам. Точные имена ключей надо сверить с
рабочим конфигом hermes (у нас он на `D:\.hermes\`), после чего поправить `hooks.json`,
а не менять контракт скриптов: скрипты специально не знают ничего про hermes.

Пока регистрация не подтверждена, оба хука полезны и без неё — их можно вызывать
вручную или из своего враппера:

```bash
# в начале сессии
bash hermes/hooks/session_start.sh
# перед пушем
echo '{"event":"pre_tool","command":"git push origin backup"}' | bash hermes/hooks/guard.sh
# в конце задачи
bash hermes/hooks/task_end.sh
```

## Чего хуки НЕ делают

* Не перезапускают процессы и не «лечат» окружение — только предупреждают и блокируют.
* Не трогают игру, браузер и мосты.
* Не решают за агента: если блокировка спорная, они объясняют причину, и человек
  может её снять, поправив правило.
