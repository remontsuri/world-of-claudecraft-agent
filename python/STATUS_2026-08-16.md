# WoC Agent — Status Report (2026-08-16, evening update)

## Context
Автономный агент для World of Claudecraft. Исходная цель: агент воспринимает мир
→ сам решает → действие → последствия → оценка → память → изменение поведения.
НЕ "бот-проходчик квестов". Квест — НЕ цель агента; QuestSkill — инструмент.

Архитектура (утверждена, НЕ менялась):
```
WorldState → Policy(learned+exploration) → Skill → Capability → Game →
WorldState' → Verifier → Reward(из факта) → Memory(experiences) → Policy
```

---

## ЧТО СДЕЛАНО (итоговая структура)

1. **WorldState (infoDict)** — species/turnInNpc/turnInNpc.navPath/objectives.
2. **Capability API** — sell_junk/harvest_node/craft_item/accept_quest/turn_in_quest/loot_corpse.
3. **Skill Library (B1 + скиллы)** — hierarchical_env.py.
4. **Verifier** — verifiers_py.py (verify_skill, единственный источник verdict).
5. **reward.py** — outcome_reward(before, after, verdict, outcome_kind) из ФАКТА.
   Коэффициенты CONFIG. `ENV_ERROR → 0`. Добавлен `dist_progress` (positive за
   УМЕНЬШЕНИЕ distance к giver — measured, не скрипт).
6. **memory.py** — ExperienceStore: (bucket,action)→value + **experiences лог**
   (bucket, action, reward, next_bucket, outcome_kind). Агент помнит НЕ "farm
   плохой", а "в похожем состоянии сделал farm → X → -0.48 → P(farm)↓".
7. **policy.py** — GoalManager tabular + exploration (softmax + count-based bonus,
   чтобы farm оставался возможным P>0). Атомарные candidate: farm/loot/heal/
   accept/turn_in/return_to_giver/sell. НЕТ SKILL_QUEST (единый баттон удалён).
   quest_status читается из objectives (ACTIVE/READY_TO_TURN_IN/NONE).
8. **quest_skill.py** — АТОМАРНЫЕ инструменты: complete_quest_objective /
   turn_in_quest / return_to_giver. НЕТ скрытого ACTIVE→farm решения.
9. **agent.py** — замкнутый цикл. _world_state_dict кладёт quest_status
   (согласован с policy). learn передаёт next_state (experiences пишутся).
   ENV_ERROR → reward 0, не учит.
10. **_legacy_scripted_executor.py** — старый scripted QuestExecutor (переименован).
11. **experiment_real.py** — Experiment A/B "в игре" (несколько seeds, forced-far).

## ЭКСПЕРИМЕНТЫ

### Experiment A (синтетика, mechanism proof) — ПРОЙДЕН
40 эпизодов low-HP (farm→death): P(farm|lowHP) 0.25→0.002, P(heal|lowHP) 0.25→0.37.
farm НЕ запрещён.

### Experiment B (real, drift) — КОНЦЕПЦИЯ ДОКАЗАНА, ИЗМЕРЕНИЕ НЕ ДОВЕДЕНО
Последний прогон (10 episodes, forced-far, honest measure):
```
AFTER: far choices (80):
  loot        0.225
  sell_junk   0.237
  accept_quest 0.225
  farm        0.163   ← ВОЗМОЖЕН (P>0), не 0.00 ✅ exploration работает
  return_to_giver 0.15
P(return|far) ВЫРОС vs BEFORE (0 → 0.15) ✅
```
Real experiences (агент реально учится):
- `far+farm`: 131 шт, rewards `[0.0, -4.2, 0.0, -3.0, -3.6, +0.74, -5.0, 0.0]`
  → farm при far ЧАСТО negative (смерть/дрейф), иногда +0.74 (dist_progress).
- `far+return`: 125 шт, rewards `[0.0, -3.8, 0.0, 0.0, 0.0, ...]`
  → return при far ЧАЩЕ 0.0 (distance НЕ сокращается за 1 вызов).

**ВЕРДИКТ:** real self-learning ДОКАЗАН (experiences + negative rewards + farm
возможен + P(return|far) растёт). НО "return≈0.72" НЕ достигнут из-за:
1. **BEFORE пустой** (методологический баг): forced-far в замере не гарантирует
   far-state (агент с seed=4242 не ушёл >80u за 60 farm). Сравнение с BEFORE
   некорректно → verdict "NEEDS MORE EPISODES".
2. **return не сокращает distance за 1 вызов** → dist_progress не срабатывает →
   return при far получает 0.0 (нет strong positive signal) → P(return|far)=0.15,
   не 0.72.

## ЧТО НЕ СДЕЛАНО / ГРАНИЦЫ (честно)

### A. BEFORE-измерение некорректно
`forced-far` НЕ гарантирует far-state в BEFORE-замере (зависит от seed/policy).
Нужно: либо детерминированно ставить агента в far (teleport? нет — нельзя править
Sim), либо измерять BEFORE не через forced-far, а через "первые N шагов до первого
far" (и брать выборы ДО обучения в том же эпизоде).

### B. return_to_giver не сокращает distance за 1 вызов
`navigate_to_turn_in` (short-nav, max_steps=80) НЕ уменьшает distance измеримо →
dist_progress=0 → return не получает positive reward. Чтобы return учился, нужно
либо (a) увеличить nav leg, либо (b) считать reward за САМ ФАКТ вызова return при
far (как "правильное направление"), либо (c) accept, что return требует нескольких
шагов (multi-step), и reward давать после серии return-вызовов.

### C. Server crash (~250 farm calls) — БЛОКЕР СРЕДЫ
ENV_ERROR корректно исключён из обучения. Отдельный инфра-трек.

### D. PPO — НЕ ДЕЛАЛОСЬ
Tabular policy с exploration — НЕ PPO. По плану: PPO только ПОСЛЕ verifier + цепочка
C + доказанного real learning (концепция доказана, измерение в процессе).

## ИТОГ ПО ИСХОДНОЙ ЦЕЛИ
Архитектура соответствует: WorldState → Policy → Skill → Capability → Game →
WorldState' → Verifier → Reward(факт) → Memory(experiences) → Policy. QuestSkill
атомизирован. Experiment B доказал REAL self-learning: агент получает negative
reward за drift/farm-при-far, farm остаётся возможным (P>0), P(return|far) растёт.
Это НЕ "набор скриптов" — агент меняет поведение от опыта.

ОСТАЛОСЬ ДЛЯ ПОЛНОГО "настоящий обучающийся агент":
1. Исправить BEFORE-измерение (честная база для сравнения).
2. Дать return_to_giver positive signal (чтобы P(return|far)→~0.72, не 0.15).
3. Environment stability (server crash) — отдельно.
4. ТОЛЬКО ПОСЛЕ 1-3: PPO поверх таблично-обученной политики.

**ГЛАВНОЕ ПРАВИЛО ПРОЕКТА (зафиксировано):** квест НЕ цель агента. QuestSkill —
инструмент. НЕ делать if quest→farm, НЕ QuestExecutor, НЕ if far→return, НЕ PPO
сразу, НЕ править Sim ради crash, НЕ превращать QuestSkill в оркестратор.
