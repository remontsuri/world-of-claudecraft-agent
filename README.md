# world-of-claudecraft-agent

Автономный агент, который **сам играет** в World of Claudecraft и **сам улучшает** свои
пороги решений. Активная линия одна — `woof-ts/`: лёгкий стек (Node 20 + TypeScript +
esbuild + vitest), мир за явным интерфейсом `World` (два транспорта: симуляция в процессе
и бридж к headless env-серверу игры), контур подбора порогов с историей.

Все факты об игре берутся **импортом из дерева игры** (`levy-street/world-of-claudecraft`,
MIT): ни одного числа, переписанного руками. Игра для нас read-only.

Прочие линии: Java-бот `woof-agent/` (заморожен 2026-09-18 — перенесён в `woof-ts`,
архитектура и дефекты описаны там же), коннектом мухи `archive/fly-line/`
(архивирован 2026-09-18 целиком, без удалений).

## Быстрые команды

```bash
bash tools/install_hooks.sh              # git-хуки: core.hooksPath=.githooks
cd woof-ts
bash tools/setup_game.sh                 # sparse-клон игры + зависимости + сборка
bash tools/check_all.sh                  # ВСЕ проверки: типы, факты, тесты, прогоны, бридж, тюнинг
node dist/run.mjs --seed 42 --steps 150 --quiet                 # стенд (in-process Sim)
bash tools/build_env.sh && node dist/run.mjs --transport ndjson --seed 42 --steps 120 --quiet   # бридж
node dist/tune.mjs --steps 150 --train-seeds 42,43 --val-seeds 44   # контур самоулучшения
```

`GAME_FULL=1 bash tools/setup_game.sh` добирает `server/**`, `src/net/**`, `src/client/**`
(нужно для WS-бриджа к живому серверу `:8787`). `SKIP_BRIDGE=1`/`SKIP_TUNE=1` ускоряют
`check_all.sh`.

Зависимости: Node 20+, git. Всё остальное ставит `setup_game.sh`; веб-фреймворков нет.
В песочнице `node_modules` стирается между ходами — поэтому любая команда, которой нужна
сборка, начинается с `setup_game.sh`.

## Эталонные прогоны (объявлены до замера)

| Мир | Бюджет | world_steps | kills | deaths | quests_done | first_turn_in |
|---|---|---|---|---|---|---|
| стенд `sim`, seed 42, warrior | 150 решений | 4323 | 24 | 22 | 2 | шаг 12 |
| стенд `sim`, seed 42, warrior | 400 решений | 6696 | 31 | 26 | 2 | шаг 12 |
| бридж `ndjson`, seed 42, warrior | 120 решений | 5530 | 2 | 0 | 1 | шаг 6 |

Повтор прогона того же сида обязан дать побайтово тот же `SUMMARY` (детерминизм проверяет
`check_all.sh`). Разница между транспортом и стендом объяснена в `woof-ts/BRIDGE.md`:
за бриджем нет id и вида сущностей, NPC виден только в 5 ярдах, накопленный урон не отдаётся.

## Приёмка — это не тесты

Тесты (62 шт. в 6 файлах, включая 15 на живом env-сервере игры) доказывают согласованность кода
и эквивалентность наблюдения. Проект закрывается **живым прогоном**: `[Agent] SUMMARY`
с настоящими убийствами и сданными квестами, фиксированный сид, детерминизм при повторе,
evidence-файл с объявленными до прогона возможностями мира, порогами и их диффом.

Пороги и целевая функция объявляются **до** замера и после него не двигаются:
`woof-ts/src/policy/params.ts` (таблица с диапазонами), `woof-ts/src/learn/objective.ts`
(веса скора). Текущие цели: полный квестовый цикл за бриджем, снижение смертей на стенде
(22 за 150 решений), робастность по сидам (D6: сид 7 хрупок — 1 убийство, 183 смерти).

## Границы, которые нельзя двигать

* Исходники игры не правим; факты игры — только импортом (сверяет `tools/verify_facts.ts`).
* Молчаливых фолбэков нет: неизвестный навык или действие, значение порога вне объявленной
  сетки, привилегированный метод мира без объявленной возможности — исключение с текстом.
* Привилегии стенда (`--npc-view 0`, полный доступ к Sim) печатаются до прогона и пишутся
  в evidence; выдавать такой результат за переносимый нельзя.
* `git push --force` запрещён. Рабочая ветка — `backup`; `master` не трогаем.
  PAT живёт только в env на одну команду и отзывается после пуша.
* `archive/` и замороженные линии — не мусорная корзина: не удаляем и не правим задним
  числом; новые факты — датированной строкой в README линии.
* Процессы `hermes-agent` и `hermes-gateway` не трогаем никогда.

## Архив

`archive/fly-line/` — линия коннектома мухи (схема на 8835 нейронов, PPO-читаут, контроли
`rewired`/`er`). Перенесена `git mv` (180 файлов), поэтому всё восстанавливается одной
командой и остаётся в истории. Итоги линии, включая отрицательные (M3 = 0 квестов во всех
85 эпизодах, `travel_norm` признана непригодной метрикой), — в `archive/fly-line/README.md`.

Тяжёлые данные архива (3 копии коннектома + канон + чек-инты, ~108 МБ) **сняты с
отслеживания**: код, документы и доказательства (`benchmark_*.json`, таблицы квестов,
`train_log_*.json`) в git остались. Отслеживаемое дерево: 117 МБ → 11 МБ.
Возврат файла — `git checkout 40f3ba6 -- <путь>`; контроли регенерируются из канона за 18 с.

`recover.py` и `dataset_collector.py` в корне — инструменты старого моста (`:8791`), к мухе
не относятся; `tools/push_backup.sh` — общий push-хелпер с проверкой fast-forward.
