# Задача B: мешает ли нам локальная Llama/Qwen? (аудит по данным)

Ты — аудитор LLM-слоя. Вопрос пользователя дословно: «мешает ли нам ллама».
Нужен ответ ДА/НЕТ/ЧАСТИЧНО с числами, а не рассуждение.

## Что такое LLM-слой в этом проекте

Локальная Qwen3.6-35B на llama-server (`http://127.0.0.1:8081`, OpenAI-совместимый
API, json_schema strict). Включается переменной окружения `WOC_BRAIN=on`.

Код:
- `python/llm_brain.py` — клиент: `decide(world, failures, lessons)` возвращает
  `{goal, reason}` из закрытого enum (ACCEPT, DO_OBJECTIVE, RETURN_TO_GIVER,
  TURN_IN, SELL_REPAIR, HEAL, SURVIVE); `should_consult(...)` — политика вызовов
  (на переходах, каждые 50 шагов, при 3 фейлах подряд).
- `python/brain_glue.py` — сборка payload (quest, ready_quests, inventory, hp)
  и `apply_decision(fsm, decision)` — запись цели в FSM.
- `python/play_autonomous.py` — вызов брейна в цикле перед `agent.step()`.

## Известные факты (проверь их сам, не верь на слово)

1. Мост и агент СЕЙЧАС ВЫКЛЮЧЕНЫ пользователем — ничего не запускай.
2. `goal_switches = 2141` на 3000 шагов (0.71 на шаг). Гипотеза: два писателя
   цели — LLM (`apply_decision`) и FSM (`update_from_world`), которые
   переписывают друг друга.
3. `quests_turned_in = 0`, `quests_completed = 0` за 3000 шагов.
4. Латентность локальной модели: измерено 1-7 с на вызов (холодный ~5-7 с,
   тёплый ~1 с при temperature=0).
5. В логе прогона встречаются строки `[brain] goal=... reason=...` — их можно
   найти в выводе процесса, но НЕ в jsonl. В jsonl есть поле `goal` на каждом шаге.

## Что нужно выяснить

**B1. Влияет ли LLM на поведение вообще?** Сравни в логе
`python/autonomous_log.jsonl` прогоны с брейном и без. Как отличить: прогоны
идут блоками (границу ищи по падению поля `t`). Прогоны с брейном — те, что
позже по времени (пользователь включил `WOC_BRAIN=on` во второй половине
истории). Дай числа: распределение действий, доля heal, kills/1000,
deaths/1000, qprog-дельта в сопоставимых окнах.

**B2. Цена в шагах.** Оцени, сколько шагов агент «теряет» на ожидании LLM.
В логе есть поле `t` (секунды с начала прогона) и `step`. Посчитай среднюю
длительность шага в прогонах с брейном и без. Разница × число шагов = цена.

**B3. Переписывается ли решение LLM?** По коду ответь: после
`apply_decision(fsm, ...)` вызывается ли `fsm.update_from_world(...)` до того,
как политика прочитает цель? Если да — решение LLM затирается фактами, и
слой бесполезен в текущей проводке. Цитируй файл:строку и порядок вызовов
в `play_autonomous.py`.

**B4. Вердикт.** Один из трёх:
- `HARMFUL` — мешает (латентность/дёрганье цели без пользы), убрать из горячего цикла;
- `NEUTRAL` — не мешает и не помогает, оставить выключенным до перепроводки;
- `USEFUL` — помогает, оставить.
Обоснуй числами из B1-B3.

**B5. Если убирать из горячего цикла — куда деть?** Предложи конкретную роль
(например: асинхронный автор hints раз в N шагов; разбор эпизодов после
смерти; генератор стратегий per-quest) + как это проверить метрикой.
