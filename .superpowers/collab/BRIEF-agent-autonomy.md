## Измеренные проблемы (последний прогон, 1221 шаг)

- kills +50, deaths +10, qprog 11→12 — прогресс есть, но **микроскопический**.
- Распределение: loot 273, fireball 268, **heal 267**, frostbolt 246, farm 167.
  Heal = 22% шагов. Агент живёт в цикле «бей → получи по морде → ешь».
- **turn_in_quest: 0 за 1221 шаг.** Сдач квестов НЕТ. Раньше пара попыток
  давала INCONCLUSIVE (гивер не в радиусе 7yd в момент вызова).
- **gather: 0**, хотя я только что добавил его в кандидаты для workorder-квестов
  и мост умеет `sim.harvestCorpse` (это путь к spider_silk для loom 5/6).
  Причина: softmax не берёт скилл с низким Q-весом из прошлых фейлов.
- Q-обучение живое, но медленное: ~6 обновлений весов за 4 минуты на 389 ключей.
- Оффлайн-merge исторических весов в живую таблицу СДЕЛАЛ ХУЖЕ (deaths +23,
  залипание в farm) — откатил. Логи содержат отравленные эпохи.
- Headless-сборка не даёт боевой награды (урон 0 даже вплотную) — тренировать
  бой офлайн нельзя, только навигацию.

## Что уже пробовал и чем это кончилось

1. Детерминированный override для RETURN_TO_GIVER/TURN_IN (не полагаться на
   softmax внутри этих фаз) — помогло, попытки return появились.
2. `has_ready` флаг: FSM больше не сбрасывает RETURN_TO_GIVER, пока есть готовый квест.
3. Фоллбек позиции гивера из nearby-NPC по questIds (у части квестов нет
   ни памяти, ни turnInNpc в снапшоте).
4. heal: убегание 3×30yd от мобов перед едой + поиск еды по itemId (было: искал
   только по def.name, который пустой → 173/192 фейла).
5. Мозгу отдали ready_quests и inventory в payload + правила в промпт.

## Вопросы, на которые нужен твой ответ

1. **Разделение ответственности.** Сейчас LLM даёт только ЦЕЛЬ (7 enum'ов), а
   выбор скилла внутри фазы — за Q-learning, который залипает. Правильно ли
   вообще оставлять Q выбор скилла? Варианты, которые я вижу:
   (а) LLM отдаёт `{goal, skill_hint}` — подсказка скилла из белого списка фазы;
   (б) внутри каждой фазы скилл детерминирован правилами, Q остаётся только
       для тактики боя (какой спелл/когда лут);
   (в) оставить как есть, но лечить Q (сброс отравленных весов, оптимистичная
       инициализация неиспробованных скиллов).
   Что выберешь и почему? Что сломается в твоём варианте?

2. **turn_in = 0.** Сдача требует: квест READY + правильный гивер в радиусе ~7yd
   + место в сумках. Сейчас скилл делает одну короткую ногу навигации и
   отдаёт INCONCLUSIVE. Как построить надёжную многошаговую доставку, чтобы
   она была измеримой (не «мега-действие всё-или-ничего») и не залипала?

3. **Цикл выживания.** 22% шагов на heal — это провал позиционирования: агент
   фармит в аггро-пачке. Нужен ли явный «безопасный периметр» (запомнить
   спокойные точки и отходить туда), или это должно рождаться из наград?

4. **Самообучение по-настоящему.** Как ускорить обучение, если офлайн-merge
   исторических логов вредит, а headless не даёт боевого сигнала? Идеи:
   приоритетное воспроизведение только post-fix эпохи, оптимистичная
   инициализация, счётчики «попробуй новое», обучение отдельных таблиц на
   фазу вместо одной общей.

5. **Что в этой структуре лишнее?** Скажи прямо, если какой-то слой — балласт.

## Формат ответа

Верни JSON по схеме (без прозы вокруг):
- `verdict`: краткая оценка текущей архитектуры (1-3 предложения)
- `answers`: массив из 5 объектов `{question: 1..5, choice, reasoning, risks}`
- `structure_proposal`: как должен выглядеть итоговый стек (компонент → роль)
- `first_three_changes`: 3 конкретных изменения в порядке приоритета, каждое
  `{what, files, test_idea, expected_metric}` — метрика измеримая
  (например «turn_in попыток > 0 за 300 шагов»)
- `disagreements`: где ты не согласен с моими решениями 1-5 выше
