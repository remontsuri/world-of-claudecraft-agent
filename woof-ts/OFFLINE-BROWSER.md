# Офлайн-браузер: агент играет в живой странице (задача C1, приёмка C1.6 = J8)

Линия: **woof-ts** (активная). Транспорт: **CDP** к вкладке с офлайн-игрой.
Наследство: поведение перенесено из замороженной Java-линии `woof-agent/`
(`tools/ref/snapshot.cjs`, `tools/ref/actions.cjs` — рабочий эталон, 1569 строк),
включая грабли, найденные там живьём. Java-сборка не используется.

Отличие от A1 (свой мир на :8787 по WS): здесь мира-сервера нет вообще — офлайн-режим
живёт внутри страницы, поэтому связь только через Chrome DevTools Protocol.

---

## 1. Что нужно на машине владельца

| Что | Зачем |
|---|---|
| Node 20+ | агент и инструменты (`npm run build`) |
| pnpm 10.34.5 | установка зависимостей игры (пин upstream) |
| Полный клон игры `levy-street/world-of-claudecraft` (~9.9 ГБ) | dev-сервер Vite :5173 |
| Chrome/Chromium/Edge | в нём живёт мир; нужен отладочный порт 9222 |
| GPU не нужен | рендер страницы достаточно лёгкий |

## 2. Порядок запуска (ровно в этом порядке)

**Шаг 1 — игра (офлайн-режим, dev-сервер Vite).**

```bash
cd <полный клон игры>
npm install -g pnpm@10.34.5
pnpm install --frozen-lockfile
pnpm run dev            # → http://localhost:5173
```

**Шаг 2 — Chrome с отладочным портом.** Отдельный профиль, чтобы не трогать свой браузер
и свои вкладки (иначе в `/json/list` будет мусор, а угадывать вкладку мы не имеем права):

```bash
# Windows
chrome --remote-debugging-port=9222 --user-data-dir=C:\chrome-cdp http://localhost:5173
# Linux
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-cdp http://localhost:5173
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-cdp http://localhost:5173
```

**Шаг 3 — войти в мир руками:** в открывшейся вкладке выбрать **«Play Offline»** →
создать/выбрать персонажа → войти в мир. Без этого `window.__game.sim.player` нет, и зонд
честно откажет (это не баг агента: входить в мир за владельца мы не будем).

**Шаг 4 — зонд (C1.1).** Доказывает, что вкладка живая, а не мёртвая с тем же URL:

```bash
cd <этот каталог woof-ts>
npm install
npm run build
node dist/cdp_probe.mjs --json evidence/offline-browser/probe.json
```

Зонд печатает: персонажа (hp/level/позиция/класс), число сущностей, `primaryId`,
**карту api страницы** (какие `sim.*`/`controller.*` действительно существуют),
состояния квестов, какие из доступных квестов мы честно берём и какие не берём (с причиной),
живые позиции NPC, способности, инвентарь, и виды сущностей вне нашей модели.

**Шаг 5 — живой прогон (C1.6 = J8).**

```bash
node dist/run_offline.mjs --steps 200 --json evidence/offline-browser/run.json
```

Флаги: `--cdp` (по умолчанию `http://127.0.0.1:9222`), `--url-hint` (по умолчанию `5173`),
`--target-id` (обязателен, если живых вкладок больше одной), `--steps`, `--max-ms`,
`--log-every` (лог каждого шага), `--quiet`, `--threshold-quests`, `--threshold-kills`.

## 3. Приёмка (объявлена ДО измерения)

* **`quests_done >= 1` И `kills >= 1`** — те же пороги, что были объявлены для J8
  в замороженной линии. Печатается в начале прогона и в вердикте в конце.
* **Правок политики под результат не делаем.** Если прогон не прошёл — это находка,
  а не повод подкрутить порог или арбитраж.
* Код возврата: 0 — приёмка пройдена, 1 — не пройдена или мир недоступен.
* Формат отчёта — тот же SUMMARY, что и в Java-линии, чтобы числа сравнивались:
  `[Agent] SUMMARY steps=… kills=… deaths=… quests_done=… first_turn_in_step=…`

Происхождение счётчиков (печатается до прогона и пишется в evidence):

| Счётчик | Источник |
|---|---|
| `quests_done` | **АВТОРИТЕТНОЕ**: число квестов с `sim.questState(qid) === 'done'` |
| `kills` | **НАБЛЮДАЕМОЕ**: переход враждебного моба alive→dead/исчезновение, пока мы в бою или с целью; сверяется с прогрессом kill-целей квеста (журнал авторитетнее — если игра засчитала больше, берём её число) |
| `deaths` | **НАБЛЮДАЕМОЕ**: переход `player.dead` false→true |
| `damageDealt/Taken` | **НЕТ**: страница не отдаёт накопленный урон → 0, как сигнал не используется |
| `copper` | со страницы (`player.copper`/`money`), если поля нет — 0 |

## 4. Возможности мира и их границы (объявляются до прогона)

`транспорт=cdp`, `абсолютные координаты=да`, `состояние любого квеста=full`,
`предметы в сумках=да`, `данные контента=да`, `детерминизм=нет`, `frameSkip=0`,
`реальное время=да`, `другие игроки=нет`, `выбор цели=free`, `идентичность сущностей=stable`,
`вид сущностей=да`, `абсолютное HP=да`, `счётчики урона=нет`, `словарь команд=page-api`.

Границы, которые нельзя замалчивать:

* **Среда привилегированная**: офлайн-dev всегда с `devCommands: import.meta.env.DEV`,
  то есть читы включены. Агент их не вызывает структурно (действует только публичными
  `sim.*` и `controller.move`), но **результаты не объявляются применимыми к честной игре**.
* **Темп задаёт страница** (`requestAnimationFrame`): детерминизма нет, повторить прогон
  шаг в шаг нельзя. Поэтому сравнение «стенд ↔ браузер» — по объявленным порогам, а не по траектории.
* **Страницу перезагружать нельзя**: `Page.reload`/`Page.navigate`/`Target.closeTarget`/
  `Browser.close`/`Input.dispatch*` запрещены структурно в `src/bridge/cdp_client.ts`
  (`FORBIDDEN_CDP_METHODS`), вызов — исключение, а не «аккуратно».
* **Ввод человека не перехватываем**: если владелец играет в той же вкладке, агент не жмёт
  клавиш и не двигает мышь — только `controller.move` и публичные методы sim.

## 5. Чего агент пока НЕ умеет в браузере (честный отказ, а не «успех»)

Не перенесены из эталона (C1.3): `gather` (сбор узлов), `craft`/`craft_item`, `sell_junk`,
`equip`, `buy`, сопровождение (escort). Навык возвращает `UNSUPPORTED:<skill>:…`, а
арбитраж эти навыки выключает заранее, чтобы не тратить на них шаги. Следствие, объявленное
до прогона: **квесты с такими целями агент не берёт** (`browserCompletable`), иначе он наберёт
то, что не может сдать (долг A2).

## 6. Что перенесено из эталона дословно (и почему)

* `required` — из `qp.resolvedCounts[i]`, `have` — из `qp.counts[i]`. Подмена давала
  «0/0 ACTIVE» на готовых квестах и наоборот, агент ходил кругами.
* `sim.questState(qid)` — авторитетен в офлайне: `available|active|done|unavailable`.
* Живые позиции NPC (`npcPositions`) важнее статических пинов из контента: таблицы
  разъезжались с реальным миром. Пины остаются запасным слоем для похода к невидимому NPC.
* `controller.face()` в офлайне — **no-op**: курс задаётся только
  `controller.move({turnLeft|turnRight|forward}, desiredFacing)`.
* **Гистерезис курса**: вход 0.35 рад, выход 0.10 рад, идти вперёд при |off| ≤ 1.20,
  состояние в `window.__navTurning`. Единый порог давал автоколебание камеры
  (баг, замеченный владельцем 2026-08-24 дважды).
* **Побег**: в бою при hp < 50% бежим ОТ ближайшего врага в пределах 25 ярдов
  (leash сбрасывает аггро). Хождение сквозь пачку дало 30 смертей за прогон.
* **Застревание**: 4 тика без движения → честное `STUCK`, а не вечный поход.
* Выбор **живой** вкладки: мёртвые вкладки с тем же URL были причиной «бот работал ни с чем».

## 7. Чего здесь нет по сравнению с эталоном (сознательно)

* Захардкоженных таблиц квестов: контент импортируется из дерева игры (`src/facts.ts`
  → `game/src/sim/data`), а не берётся из страницы (`questDefs`/`npcDefs` она отдаёт ненадёжно).
* Доспавна квестодателей через `sim.addEntity`: мир не подделываем. Если NPC не виден —
  это находка зонда, а не повод нарисовать его.
* HTTP-моста на :8791 и MCP на :8792: агент говорит с вкладкой напрямую, слушать нечего.
  Долг J12 замороженной линии (мост на `0.0.0.0` без токена) закрыт отсутствием сокета.
* Фейковых CDP-серверов на 9231/9232: полигон исполняет страничный код через
  `new Function` против фейкового `window.__game` — без портов. Долг J11 (`EADDRINUSE`
  в каждом прогоне) закрыт конструкцией.

## 8. Проверка без браузера (полигон) и полный гейт

```bash
npx vitest run tests/browser_world.test.ts      # 26 проверок, включая приёмку J8 на полигоне
bash tools/check_all.sh                          # весь гейт линии; шаг 8 — браузерная линия
```

Шаг 8 гейта проверяет: полигон зелёный; приёмка J8 на полигоне
(«взять квест → убить → сдать») проходит; инструменты собраны; **без Chrome зонд и раннер
отказывают кодом 1 и дают инструкцию**, а раннер печатает пороги до измерения.

## 9. Правила, которые нельзя нарушать (наследуются из AGENTS.md)

1. Не убивать `hermes-agent` / `hermes-gateway`.
2. Не перезагружать игру через CDP и не перенаправлять вкладку.
3. Не трогать исходники игры (дерево игры — read-only).
4. Не запускать игру, если владелец уже в ней.
5. Не перезапускать агента после правок кода — только по явной команде владельца.
6. Не исправлять политику/пороги под результат прогона.
