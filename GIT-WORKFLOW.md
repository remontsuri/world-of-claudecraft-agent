# Ветки и пуш: как это работает у нас

Короткая политика, выведенная из двух реальных провалов: «локальная история разошлась
с remote, а мы этого не заметили» и «чуть не переписали чужую версию каталога».

## Роли веток

| Ветка | Роль | Что можно |
|---|---|---|
| `master` | стабильная линия владельца репозитория | **ничего**: не пушим, не переписываем. Изменения туда попадают только решением владельца |
| `backup` | наша рабочая ветка, источник истины по нашей работе | обычные fast-forward пуши |
| топик-ветки (`woof-agent/...`, `fly/...`) | возможны для крупных экспериментов | создаются от `backup`, вливаются в `backup` fast-forward; на remote — только если это обговорено |

Скрипт-помощник для пушей: `fly-woc/push_fixes.sh` (пушит в `backup`).
Пример команды с токеном из окружения и inline-helper (токен не пишется в конфиг):

```bash
GH_TOKEN=<pat> git -c credential.helper='!f(){ echo username=x-access-token; echo password="$GH_TOKEN"; };f' \
  push origin HEAD:refs/heads/backup
```

## Протокол перед пушем (обязательный)

1. **Свежий клон** (не «у меня же есть локальная копия»):
   `git clone --branch backup ... /tmp/pushrepo`.
2. **Проверить предка**: `git merge-base --is-ancestor origin/backup HEAD && echo fast-forward`.
   Если не предок — **не пушить**, разбираться: скорее всего, история разошлась
   (у нас так и было: те же фиксы, но другие SHA).
3. **Сверить содержимое**, а не историю: `git diff --stat origin/backup HEAD` — в диффе
   должны быть только наши изменения. Если появляются удаления чужих файлов — стоп
   и разбор.
4. **Прогнать проверки на том самом дереве**, которое поедет (`hermes/TOOLS.md`).
5. **Пуш** без `--force`, затем **проверка remote**: `git ls-remote ... refs/heads/backup`
   и `git log origin/backup -3`.
6. **Скан следов токена** после пуша и отзыв токена.

## Оформление коммитов

* Типы: `feat`, `fix`, `docs`, `test`, `chore`.
* Область в скобках: `feat(woof-agent): ...`, `docs(knowledge): ...`.
* В теле — **что стало правдой** и **чем это проверено** (команда + ожидаемая строка).
  Наши коммиты — это ещё и отчёт: через месяц по ним видно, почему решение принято.
* Один коммит — одна причина. Документацию отдельно от кода: так ревью и откат дешевле.

## Что не коммитим

* `build/`, `*.class`, логи прогонов, дампы, `_snap*.json`, `.hermes-tmp.*` — см. `.gitignore`.
* Файлы > 100 МБ и веса коннектома (`connectome-weights.feather`): LFS исчерпан,
  большие артефакты — только в Releases.
* Секреты: токены, ключи, PAT. Токен живёт одну команду и не попадает ни в файлы,
  ни в `.git/config`.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| пуш отклонён «non-fast-forward» | не форсить. Свежий клон, `merge-base`, понять, чей коммит сверху, и переносить свои изменения поверх (cherry-pick), а не «продавливать» |
| расхождение истории при равном содержании | сверить деревья (`git diff --stat`), зафиксировать вывод, дальше работать от remote-версии |
| случайно закоммичен секрет | сменить/отозвать секрет сразу, затем переписать историю **только по согласованию с владельцем** (общая ветка — не игрушка) |
| чужой процесс держит порт тестов | сначала разобраться, чей он; убивать только свои инструменты (`fake_cdp.cjs`, `fake_bridge.cjs`, `browser_bridge.cjs`) |
