# Артефакты прогонов: что здесь лежит и что из этого следует

Правило проекта: результат без артефакта — это пересказ. Здесь лежат чек-инты читаута
и отчёты бенчмарка, по которым можно **перепроверить** заявления из `knowledge/`.

## Бенчмарки (условия и числа)

Все прогоны: `world-of-claudecraft` (levy-street, headless env_server), obs=607,
actions=61, 5 эпизодов × 1200 шагов, `seed0=900001`, класс warrior.
Числа — `mean_reward` / `total_quests` / `mean_xp` / `total_kills` / `total_deaths`.

### `benchmark_v2.json` — включены абляции

| Условие | reward | quests | xp | kills | deaths |
|---|---|---|---|---|---|
| `fly` (argmax) | 1.2 | 0 | 0 | 0 | 0 |
| **`fly-sampled`** | **19.266** | **4** | **48** | 0 | 0 |
| `fly-sampled-silenced` | 1.2 | 0 | 0 | 0 | 0 |
| `fly-sampled-untrained` | 1.2 | 0 | 0 | 0 | 0 |
| `mlp` | 1.2 | 0 | 0 | 0 | 0 |
| `mlp-sampled` | 1.4508 | 0 | 0 | 0 | 0 |
| `fly-silenced` | 1.2 | 0 | 0 | 0 | 0 |
| `fly-untrained` | 1.2 | 0 | 0 | 0 | 0 |
| `random` | −4.483 | 0 | 13.2 | 1 | 6 |
| `openloop` | −69.2746 | 0 | 0 | 0 | 70 |

Что это значит (строго): единственное условие с прогрессом — `fly-sampled` (4 квеста).
Стоит выключить схему (`silenced`) или взять необученный читаут (`untrained`) — прогресс
исчезает (0 квестов, reward 1.2 = «ничего не происходит»). MLP на тех же входах тоже 0.
То есть **на этом прогоне** прогресс требует одновременно живой схемы и обученного читаута.

Чего здесь **нет** и что нельзя утверждать:

* контроей `rewired` и `er` в этом бенчмарке не было — значит, «коннектом полезнее
  перепутанной копии» из этих чисел не следует (это задача F8 в `ROADMAP.md`);
* прогон один (5 эпизодов, сиды 900001–900005), а не три сида;
* `fly` (argmax) и `fly-sampled` ведут себя по-разному на одном чек-инте. Два
  равноправных объяснения (не вывод!): сэмплирование даёт нужное исследование,
  либо argmax обученного читаута вырождается в повторяющееся действие. Это надо
  различать отдельным замером (гистограмма действий и число уникальных действий).

### `benchmark.json` — ранняя версия, без сэмплированных абляций

| Условие | reward | quests |
|---|---|---|
| `fly`, `fly-sampled`, `fly-silenced`, `fly-untrained`, `openloop` | 1.2 | 0 |
| `random` | −1.7508 | 0 |

Вывод: до появления `-sampled` условий прогресса не было ни у одного варианта схемы —
полезно как «до/после», а не как доказательство.

### `benchmark_default-rewards.json` — награды по умолчанию

`fly` 0.0, `fly-silenced` 0.0, `fly-untrained` 0.0, `random` −1.2832, `openloop` −70.4746,
квестов нет ни у кого: форма награды здесь не даёт сигнала (см. `REMAINING.md`).

## Чек-инты читаута (`params_*.pt`)

| Файл | Что это |
|---|---|
| `params_fly.pt` | базовый чек-инт фазы 1 (тот, с которым взят M0) |
| `params_fly_default.pt` | фаза 1 на наградах по умолчанию |

## Логи обучения (`train_log_*.json`, `log_*.txt`)

`config` (полные аргументы прогона) + `log` (по апдейтам: reward, эпизоды, kills, уровень,
oracle-шейпинг) + `env_crashes`. Логи A/B: `train_log_fly_rd_narrow.json`,
`train_log_fly_rd_wide.json` (по 5 апдейтов — **не вывод**, только заготовка),
`train_log_fly_rd2_narrow.json` (25 записанных обновлений, 1 эпизод, ret −5.057),
`log_rd2_narrow.txt` (сырой вывод того же прогона, включая предупреждение о `float(pg)`,
которое потом исправили).

## Как перепроверить

```bash
# тот же бенчмарк по сохранённым чек-интам (нужна машина с игрой)
python3 fly-woc/progress_eval.py --device cpu --conditions fly,fly-sampled,fly-silenced,fly-untrained,mlp
# метрики M1–M4 и ступени
bash fly-woc/tools/accel_m1_m3.sh
```

Важно: чек-инты читаута **несовместимы** между версиями схемы и разными контроллерами —
при смене `circuit.json` или контроля обучай читаут заново (урок FalinX/fly-brain).
