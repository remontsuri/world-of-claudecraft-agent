# Архитектура fly-линии

Как устроена линия «коннектом играет в World of Claudecraft». Карта файлов —
`FILES.md`, чек-лист для GPU — `GPU-DEVICE.md`, план — `ROADMAP.md`, обзор чужих
подходов и лицензий — `ECOSYSTEM.md`.

## 1. Что именно мы делаем

Схема коннектома (8835 узлов, 1.87M рёбер) **не обучается**. Она — фиксированный
преобразователь: наблюдение игры → активность выходных нейронов (82 DN) → читаут
(actor/critic) → действие в игре. Обучается только читаут. Это принципиально:

* «муха обучается» — это про читаут и PPO, а не про веса коннектома;
* любое сравнение с контрольной схемой (rewired/ER) идёт **теми же** читаутом,
  сидами и входами — иначе сравниваем не схемы, а обучение;
* пары «энкодер + читаут» нельзя переносить между версиями и контроллерами
  (урок FalinX/fly-brain: обученный на другом контроллере readout сделал игру хуже).

## 2. Слои

```
игра (levy-street/world-of-claudecraft, офлайн)
  └─ node-симуляция: python/wow_env.py (env_server, frameSkip 5, maxSteps 8000)
        │  наблюдение obs (длиной 567/587/607 — зависит от сборки)
        ▼
obs_layout.py ─── раскладка полей выводится ИЗ ЗАМЕРА сборки (не угадывается по длине)
quest_oracle.py ─ таблицы по сборкам (204/214/224), 5-мерный боковой канал + шейпинг
        ▼
fly_brain.py :: extract_features (13 каналов) ──► FlyBrain (circuit.json)
        │                                            ├─ backend scipy  (CPU-эталон)
        │                                            ├─ backend edge   (gather+index_add, GPU)
        │                                            └─ backend sparse (torch.sparse, сверка)
        │  состояние h живёт на выбранном устройстве (device_utils.py)
        ▼  активность 82 DN
agent.py :: FlyBrainReadout (DN → actor/critic)   ← обучается; MLPControl — baseline
        ▼
train.py :: Runner + PPO (+ опц. oracle-канал, маска способностей по GCD)
        ▼
игровые действия ──► среда ──► отчёт progress_eval.py (M0–M4)
```

## 3. Выбор устройства (`device_utils.py`)

Приоритет: `--device` → `WOC_DEVICE` → `cuda` → `mps` → `cpu`.
Явно запрошенное недоступное устройство — **ошибка**, не тихий откат.

| Бэкенд схемы | Где уместен | Как считается |
|---|---|---|
| `scipy` | CPU (эталон) | `csr_matrix` из весов, `W_T @ h.T` |
| `edge` | GPU (основной) | `index_select` по пре-узлам + `index_add_` в пост-узлы |
| `sparse` | сверка | `torch.sparse.mm` |

Выбор: `backend` аргумент → `WOC_BRAIN_BACKEND` → `auto` (cpu → `scipy`, иначе `edge`).
Проверено: `edge`/`sparse` совпадают со `scipy` с точностью ≤ 3e-8.

## 4. Динамика

Сейчас: leaky-tanh, три итерации, `h = (1−leak)·h + leak·tanh(u + gain·rec)`,
драйв `u[:, input] = 2·(x[ch] − 0.5)`, выход `4·h[DN]`.

Следующий шаг (объявлен в плане): conductance-LIF из `src/fly_brain/engine.py`
(`tauSyn 5 мс`, `tDelay 1.8`, `tauMem 10`, `vTh −50 мВ`, `tRefrac 2`). Переносится
своя же реализация, а не чужой пакет: внешний `flybrain` (MIT) — эталон для сверки
статистики DN, не источник кода.

## 5. Данные схемы

`data/circuit.json` (25 МБ на диске): 8835 узлов, 1 874 865 рёбер, 52 входа,
82 выхода DN, 13 каналов. Веса — счётчики контактов (1…1601, положительные),
знак берётся у пресинаптического нейрона; нормализация входящих:

```
W[post, pre] = contacts · sign[pre] / Σ_k contacts·|sign[k]|   (по входящим в post)
```

Читается **потоково** (`load_circuit`): `json.loads` строил 1.87M вложенных списков
(~0.6 ГБ пик, ~0.5 ГБ оставалось на каждую копию мозга). Теперь пик разбора ~0.34 ГБ,
в мозге живут только метаданные (~9 тыс. элементов). Страж — в `tools/test_device.py`.

## 6. Контроли

`tools/make_control_graph.py`: `--mode degree` (обмен рёбер — in/out-степени **точно**
сохраняются, граф простой, вес остаётся на ребре) и `--mode er` (Эрдёш–Реньи с теми же
N и M, петли исключены, мультимножество весов то же). В файл пишется блок `control`
с sha источника и seed. Проверено на полной схеме: degree — 39.4 % пар изменено,
петли 7→7; er — 100 % пар, петли 7→0.

Набор условий для сравнения: `our` / `rewired` / `er` / `MLP` / `silenced` / `untrained`.
Пороги M1–M4 объявляются заранее и после замера не двигаются.

## 7. Замеры и оценки (что известно точно)

| Что | Значение | Чем получено |
|---|---|---|
| Разбор схемы | 3.1 с, пик 337 МБ | `load_circuit` на `data/circuit.json` |
| Шаг схемы, CPU, B=4 | `scipy` 62.3 мс · `sparse` 256.7 · `edge` 843.5 | приёмочный замер |
| Эквивалентность бэкендов | `edge` 8.9e-08, `sparse` 6.0e-08 (max\|Δ\|) | там же |
| Шаг среды | ~200 мс (frameSkip 5) | наблюдение прогонов |
| M0 | взят: `39.47`, 1 квест, шаг 724 | `progress_eval.py` |

Вывод из чисел: на CPU осмысленен только `scipy` (поэтому `auto` его и берёт);
`edge` — это про GPU, где ожидаем единицы миллисекунд на шаг. Реальные цифры с картой
снимаются `tools/gpu_check.py --device cuda --bench` на машине пользователя.

## 8. Что уже доказано, а что нет

**Доказано (с командой):**

* `run_checks.sh` 6/6; `test_device.py` 25 проверок; контроли топологии на полной схеме;
* I/O sanity: наблюдение действительно приводит схему в движение (`check_io.py`);
* схема читается потоково и не утекает памятью.

**Не доказано (и это честно записано):**

* что коннектом полезнее своей перепутанной копии — контроль rewired/ER ещё не прогнан
  на обучении;
* M1–M4 на живой игре (нужна машина с GPU и игрой);
* LIF вместо leaky-tanh — не перенесён.

## 9. Границы

Игру не патчим и не перезагружаем; полные веса CNS не качаем и полномасштабную
тренировку не запускаем без явного подтверждения; `--force` push запрещён;
рабочая ветка — `backup` (см. корневой `GIT-WORKFLOW.md`).
