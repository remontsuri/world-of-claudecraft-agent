# Визуальные среды: чем смотреть на нашу муху и на её мозг

Срез 2026-09-17. Все ссылки прогнаны HTTP-запросом в этот день (код ответа указан).
Задача раздела — не рисовать свой 3D-рендер (он уже есть у людей), а вставить наши
данные в готовые вьюеры. Рисовать самим имеет смысл только то, чего нет ни у кого:
трассу нашего прогона внутри игры (см. §5).

## 4. Как посмотреть наши 8835 клеток (пошагово)

```bash
cd fly-woc
python3 tools/viz_export.py            # соберёт viz/scene-*.json (аннотации скачает сам, 14 МБ)

# вариант А — свой вьюер (рекомендую: ничего не хостится)
pip install neuroglancer
python3 tools/serve_viz.py --viewer    # печатает http://127.0.0.1:<порт>/v/<токен>/ — открыть в браузере

# вариант Б — публичный клиент + локальная раздача сцены (CORS уже включён)
python3 tools/serve_viz.py
# затем открыть ссылку, которую он печатает, вида
#   https://neuroglancer-demo.appspot.com/#!http://localhost:8790/scene-full.json
```

В сцене: `our-somas-descending` (красные точки, 1308) — нисходящие, `our-somas-input`
(зелёные, 36) — входные клетки, `our-somas-interneuron` (серые, 7233) — внутренние,
оранжевые меши в слое `cns-seg` — **те 82 нисходящих, которыми агент реально играет**.
258 клеток без сомы — у них `somaLocation` в датасете не заполнен, это норма.

Требование к браузеру: WebGL 2.0 и `EXT_color_buffer_float`. Данные слоёв тянутся
напрямую из Google Storage Janelia (открытый CORS), у нас ничего не хостится.

## 5. Что смотреть по игре (этого во внешних средах нет)

Ни одна из таблиц выше не показывает **нашу трассу**: как агент ходит по миру, какие
действия жмёт, какие из 82 нисходящих горят. Для этого у нас своё (и оно самодостаточно —
открывается двойным щелчком, без сети):

```bash
WOC_PYTHON_PATH=/home/user/woc-hat/python python3 tools/record_replay.py \
    --steps 8000 --stride 2 --out replay.json
python3 tools/render_replay.py replay.json muha.html
```

Прогон на 8000 шагов (сборка v0.42.2, obs=607): один квест сдан, xp 60, путь 5857 юнитов,
цель квеста бралась на дистанции до 568 и сокращалась до 2.5 юнитов.

## 6. Честные ограничения

- **Активности во времени в Neuroglancer нет.** Цвет сегмента задаётся состоянием сцены,
  «плеера по кадрам» для спайков там не предусмотрено. Если хочется смотреть, как
  вспыхивают наши 82 нисходящих в 3D по ходу прогона, вариантов два: (а) генерировать
  серию сцен/кадров, (б) `navis` + plotly в Python (умеет цвет по значению и кадры), и
  тогда вьюер — питоновский, а не браузерный. Это отдельная работа, не «включить галочку».
- **Codex требует входа через Google**, а часть инструментов работает на серверах
  Princeton — это чужая инфраструктура, доступность от нас не зависит.
- **neuPrint: шаблон ссылки** с `qr[0][pm][bodyIds]` — схема из их трекера задач, я её не
  исполнял в браузере (нет JS-окружения). Если не сработает — нужный bodyId просто
  вставляется в поиск руками.
- **Прямые ссылки на сцену у нас пока локальные** (нужен `serve_viz.py`): публичный
  CORS-хостинг сцены = коммит `viz/` в `backup` + raw.githubusercontent (он отдаёт
  `Access-Control-Allow-Origin: *`). Файлы готовы, коммита пока нет.
- **FlyGym/Fly.exe — про тело, а не про игру.** Перенос нашей схемы в MuJoCo-тело — это
  другая задача (нужен контроллер «нейроны → мышцы/суставы»), а не переключатель вьюера.
